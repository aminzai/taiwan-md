## 為什麼不直接修

技術上加 `:lang(ja)` 覆寫很小。但它牽動三件不屬於例行維護的事：

1. **品牌識別**：字型是視覺身份的一部分，per MANIFESTO §自主權邊界
2. **justfont**：`jf-jinxuanlatte` / `jf-lanyangming` 是 justfont 的繁中 webfont，日文沒有對應款。日文版要嘛換掉這層（失去 justfont 的字感），要嘛只覆寫 fallback 那層（jf 字型仍以繁中字形顯示 kanji）。而且 justfont 的網域設定本來就卡在 #1184
3. **載入成本**：Noto Sans/Serif JP 是另一組完整 CJK 字重，日文讀者的首屏會多背一份

## 三個選項

|            | 做法                                                                                                                                  | 成本                          | 效果                                                                          |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- | ----------------------------------------------------------------------------- |
| **A 最小** | `:lang(ja)`／`:lang(ko)` 只覆寫系統字型 fallback（`Hiragino Sans`／`Yu Gothic`／`Meiryo`／`Malgun Gothic`），不動 webfont、不新增載入 | 幾行 CSS，0 網路成本          | 有裝日文系統字型的讀者（macOS／Windows 日文環境）立刻正確；其他人仍看繁中字形 |
| **B 完整** | A 再加 Google Fonts 條件載入 Noto Sans JP／Serif JP                                                                                   | 多一組 CJK 字重，需量首屏影響 | 所有日文讀者都正確，與 justfont 字感不一致                                    |
| **C 不做** | 維持現狀                                                                                                                              | 0                             | 日韓讀者持續看繁中字形                                                        |

**推薦 default：A**。它把「字形錯」修掉在絕大多數真正會在意的讀者身上（在日文環境讀日文頁的人），不動 justfont、不加載入成本、可逆，也不預先替 B 的字型選擇做決定。B 可以等 A 上線後看 GA 的 ja 流量再評估值不值得。

要哪一個跟我說，A 我可以當天做完。
