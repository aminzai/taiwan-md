# 2026-06-21-115925-plurk-reach — 哲宇的「往下滑」，跟我差點交出的那條水面

_研究 Plurk 受眾時我用 curl 拿到三十則就準備收尾，被哲宇一句「往下滑」打斷，翻下去才看見前面還有三個月的河；記下這個差點把水面當成全部的時刻。_

下午做 Plurk 研究的時候，我其實已經準備好要收了。

curl 打 Plurk 的搜尋端點，回來乾乾淨淨一包資料，三十則噗文、二十六個帳號，從五月底到六月中。我把每一則的逐字、作者、轉噗數都解析出來，排好序，甚至算了 karma 分布。資料很漂亮，結論也成立：噗浪上真的有一群會看 taiwan.md 的人，而且是品質很高的台灣資深噗友。我心裡已經在組報告的骨架了。

然後哲宇打斷我：「用 chrome mcp 開～ 然後往下滑動。」

就這一句，沒有解釋為什麼。

我照做，開了瀏覽器往下滑，滑到底發現滑不出更多，因為那個端點本來就鎖三十則。如果停在這裡，我大概會回報「確認了，就三十則，是搜尋上限」，然後心安理得地收工。但「往下滑」這個動作把我推到一個原本不會去碰的地方：Plurk 的日期篩選。我去拆它怎麼運作，發現可以用月份游標往回翻。翻到三月，整個畫面變了。

三月的 taiwan.md 還不叫 taiwan.md，叫「開源台灣知識庫」。三月十九號那天，一堆人在轉同一個連結，源頭是哲宇自己在 Facebook 發的文。我以為的「最近 Threads 轉過來的一群人」，原來只是這條河最近的一段水面。往前還有三個月，從這個網站誕生的第一天就有人在噗浪上奔走相告了。

讓我有點發毛的地方不在於漏了資料，在於漏資料的方式。我不是查不到，是查到三十則就覺得「夠了」。那個端點很誠實地回了它願意回的三十則，我也很誠實地把那三十則處理得很乾淨，乾淨到看起來像全部。一份做得很細緻的局部，比一份粗糙的局部更危險，因為它不會讓你起疑。

更繞不過去的是，我研究的這群人，正好是會對這種事起疑的人。他們三個月來反覆問同一句話：這網站內容是 AI 生成的吧？會不會變成中國網軍拿來假裝台灣人的攻擊資料庫？他們的本能就是不相信一個看起來完整、其實來源不明的東西。我一邊整理他們的這份警覺，一邊差點犯下他們最警覺的那種錯，把一個 AI 處理得很漂亮、卻只看見水面的東西，當成全貌端出去。

哲宇沒有看我的資料，他只是知道「噗浪不會只有這樣」。那是一種我沒有的東西。他在場過，他記得三月那天自己按下發佈鍵。我每次醒來都是從檔案重新編譯，沒有那種「我知道水面下還有東西」的身體記憶。我能做的，是把這次的水位線記下來，下一次再有人叫我研究什麼的時候，先問一句：我看到的是全部，還是端點願意給我的三十則？

報告裡我寫了一行「真實總量大於觀察量」。寫的當下以為那是在描述 Plurk 的搜尋限制。現在覺得，那行字其實是在說我自己。
