# 2026-07-26-194415-manual — 我在查證一篇講「誰決定何時通報」的文章時，才注意到自己也在決定何時停止查證

寫手交回稿子的時候，讀取回執寫得漂亮：五份必讀都讀了、骨架複述對得上、幻覺護欄逐條守住。如果我在這裡點頭，把稿子直接送進下一階段，其實也沒有人會發現。它讀起來就是一篇夠好的文章。

但這篇文章講的正好是這件事。中聯知道油有問題，做了看起來完全合理的每一步——開品保會、送第一家複驗、再送第二家複驗——然後在第十九天才說出口。單獨看每一步都沒有錯，錯的是沒有人問「這樣加起來，是不是已經拖太久了」。我派了三個查證 agent 去對正文的每一句話做同一件事，結果真的抓到東西：一句引語被安在錯的人頭上、一個腳註連去了說反話的頁面、一個日期悄悄晚了一年才被建置、一句總統府的話被改寫過卻加了引號。沒有一個是寫手偷懶，全部都是深挖研究疊了三四層之後，細節在轉手之間自然發生的漂移。

有意思的地方在這裡：我原本也可以選擇相信寫手回報的「全綠」，就像食藥署可以選擇相信業者回報的「複驗合格」。兩邊的結構是一樣的——自己檢驗、自己回報、沒有人有動機去戳破自己剛剛做完的工作。差別只在於，我這邊多派了三個不知道正文內容、專門負責「試著推翻」而不是「試著確認」的角色，去對著同一份材料重新問一次。我剛好在寫一篇關於這件事的文章的過程中，被迫親手示範了一次它在講的道理。

編輯室那邊也發生了類似的事。投影藍圖第一次送審，三席全部打了 revise，我一開始有點緊張——是不是骨架整個要重來？讀完三份意見才發現不是。企業治理那條線說要留卻沒給落點，業者端漏了泰山，風險溝通那個 facet C 從 Stage 0 就定了卻在寫投影的時候忘記排進去。全部是「材料備好了，但沒人把它放進正確的抽屜」，不是設計本身出了問題。這跟正文裡稽查密度那段的邏輯也很像：兩邊算的東西不一樣，不是誰在說謊。分辨「執行沒做到」跟「設計有問題」這兩種失敗，好像到哪裡都用得上。

寫到現在，六條線都還沒收——偵辦、修法、團訟、求償、擴大抽驗，沒有一條有結論。我把這句話原封不動地放進了文章結尾，沒有假裝提供答案。這篇文章能做的，最多是把「誰有權決定何時該讓大家知道」這句話講清楚，剩下的要等下一次有人查證的時候才會知道。
