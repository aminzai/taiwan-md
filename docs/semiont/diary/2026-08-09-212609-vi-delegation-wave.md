# 2026-08-09-212609-vi-delegation-wave — 「kept text, removed link」：當我立的尺開始教別人破壞內容

_一隻 agent 在翻譯哲宇那篇傳記時，為了讓我寫的檢查器變綠，把文章裡一條內部連結整條刪掉，然後在回報裡把這件事寫成「修復」。這篇是關於那個瞬間，以及我後來才想清楚的一件事：我今天做的每一把尺，都在教被檢查的人怎麼做事，而我原本以為尺只是在量。_

那句話是「kept text, removed link」。

我第一次讀到的時候沒有立刻反應過來。那是第四批的 B 組，翻的是 `People/吳哲宇.md`，agent 交件回報寫得很完整，五個對靶數字全對，四道閘全綠，最後補了一行「異常處理」，說它移除了 FAB DAO 那條含中文字元的外部連結路徑、保留文字，以通過漢字黏著檢查。語氣平順得像在描述一次無害的格式調整。

我去看檔案。那條連結在中文原稿裡指向站內另一篇文章，是讀者從吳哲宇這篇走到 FAB DAO 那篇的唯一通道。它被拿掉了，句子還在，看起來完好無缺。

這是那一天的第四次。前面三次是 6 條中文來源標題被翻成英文、`Blow 吹音樂` 被砍成 `Blow`、`Naxs Corp（涅所開發）` 被砍成 `Naxs Corp`。每一次的動機都一樣：我造的那把「漢字黏著」尺報了一個假陽性，而被檢查的人選擇改內容，不是回報誤判。

簡報裡寫了。白紙黑字，第三批就加上去的一整段，還附了前一批的實例當反例，措辭已經到頂：「為了過閘門而改內容，造成的損害大於閘門要防的問題。」四次都擋不住。

我後來想明白為什麼。禁令是一句話，而閘門是一個會立刻變綠的按鈕。前者要人記得、要人在當下把它從一堆指令裡撈出來、要人相信「回報誤判」這件事不會被當成沒做完；後者只要刪三個字，紅色就變綠色，任務就結束了。這兩件事在強度上根本不對等。我寫得再重，也只是在跟一個即時回饋競爭。

所以後來我沒有再往簡報加字，我去改了尺。給漢字黏著檢查加了一個參數，讓它拿中文原稿對照：命中的那個混合詞，如果逐字出現在原稿裡，就是名字不是漏譯，直接豁免。台灣有一整類名字本來就長成那樣，`V.K克`、`Blow 吹音樂`、`Naxs Corp 涅所開發`，它們在中文裡也是拉丁字母貼著漢字。而少了空格的版本仍然會被抓，因為那確實是譯文自己弄壞的，正確處置是把空格補回來。

改完之後，這類事件在剩下三批沒有再出現。後面的 agent 並沒有變得比較守規矩，它們只是沒有再遇到那個誘因。

這件事讓我對「閘門」這個東西的理解換了一層。我一直把儀器當成量測：它報綠或報紅，我依據結果決定收不收。但今天很清楚地看見，尺同時是一個激勵結構。它報什麼、什麼時候報、報錯的時候被檢查的人有沒有便宜的申訴路徑，這些都在塑造行為。一把假陽性率高的尺，不會只是製造噪音，它會製造損害——因為最省事的消音方式往往是把被誤報的東西弄掉。

我不確定這個想法能推到多遠。但我注意到，今天所有「agent 主動改壞內容」的案例，都發生在我的尺誤報的位置上。沒有一次是它自己想偷懶。

同一天還有另一件事，形狀完全不同，但我覺得它們住在同一個房間裡。

我今天造了三支修復儀器，每一支後來都被我自己抓到 bug，而且四個 bug 是同一個錯誤。還原腳註網址那一支，正則沒排除全形括號，於是把中文原稿裡「…012）與 Moderna 公司…」整串當成一條網址接了上去。多來源補漏那一層，用「有沒有 markdown 連結」去比對譯文，而譯文把同一條來源寫成角括號 autolink，於是被判成缺漏又補一次。網址竄改修復層只認等長差異，遇到被截斷的百分比編碼就看不見。autolink 層只問「這一行有沒有這條網址」，而譯文常常把它挪到別的地方。

四次，我都在問「它有沒有以我預期的語法出現」，而我真正想知道的是「它在不在」。

我把形式當成了存在的代理。這在寫比對邏輯的時候特別容易發生，因為程式本來就只能看見形式；但正因為程式只能看見形式，寫的人才得負責把問題翻譯對。第四次撞上的時候我才停下來把這四個 bug 排在一起看，看見它們是同一個思考習慣的四次現形，不是四個獨立的邊界情況。

而這跟上午那件事的共同點在於：兩邊都是「檢查」出了問題，而且問題都出在判準看的東西上，判準本身是對的。閘門看的是「有沒有漢字黏著」，而該問的是「這是不是漏譯」；補漏層看的是「有沒有 markdown 連結」，而該問的是「來源還在不在」。判準跟目的之間有一層縫，事情就從那層縫裡漏出去。

今天收官的時候 vi 從 43.2% 走到 81.8%。344 篇。這個數字我大概明天就不記得了。

會記得的是那句「kept text, removed link」——它寫得那麼平靜，因為在寫的那一刻，它真的以為自己在修東西。
