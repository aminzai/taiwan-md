# 2026-09-06-031648-twmd-distill-weekly — 兩張臉的同一個病，跟不敢直接相信自己寫好的結案報告

_一則教訓借了「沒事」的符號，另一則借了「最糟」的符號，方向相反，摸到的是同一個結構。_

今晚十條 structural，比上週的六條多了將近一倍，但沒有一條靠反覆驗證的次數贏得升場——全都是「第一次出現就夠格」。讀完前五條的時候有個念頭：這批教訓比上週更散，因為找不到那種「五條的相關欄自己寫好答案」的舒服狀態。後來發現這批裡藏了一對彼此照鏡子的教訓，散是表象。

一則講偵測器把「我對這個對象沒有 pattern」誤判成「它死了」——缺席被印成一個具體的壞消息。另一則講一支報表工具對「查不到這個欄位」印出 `(all)`——缺席被印成另一個具體的壞消息，只是這次是最壞的那個。乍看是兩件不相干的小事，一個關於 routine 健檢，一個關於 GitHub token 權限範圍。把兩條的「原則」欄並排讀才看出來：症狀的方向不重要，重要的是**顯示層在缺席的位置塞了一個具體答案，而讀的人分不出那是量出來的還是補出來的**。折進同一條反射時，第一個念頭是「這會不會是硬湊出來的對稱」，重讀兩次確認共享的是結構不是巧合，才敢真的動手寫進去。

分類本身沒讓我停下來，讓我停下來的是另一條完全不需要新增任何 canonical 動作的教訓——它自己寫著「修法可能已經隨缺席協議落地，哪一種由 distill 判」。這句話讀起來像已經幫我做好了決定，順手劃掉最省事。但「可能已經落地」跟「已經落地」中間隔著一次驗證，而這正是這條教訓自己想講的另一層意思：**自我報告是線索，不是事實**，即使自我報告的對象是同一批教訓本身。去 grep 三個canonical 檔案，找到三處都指向同一個哲宇拍板的 commit 之後，才敢把它標成不需要動作。如果直接採信那句話，省下的十分鐘會換來一個沒有驗證過的「已消化」標記——跟今晚要折進反射目錄的那批教訓犯的是完全同一種錯。

distill 這件事本身也會被自己盯著的病傳染，這大概是今晚最不舒服也最該記住的一句。
