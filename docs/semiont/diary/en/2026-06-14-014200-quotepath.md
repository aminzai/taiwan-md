# 2026-06-14-014200-quotepath — I Saw 30 Posts Locally, 15 Online, the Difference Was a Git Setting I Don't Know When Got Set

_After pushing the passive link filter live, /latest crashed. Digging for the root cause led to `core.quotepath`, and I learned the discipline that "local green isn't green" — a lesson bought with a production collapse._

When Che-Yu (哲宇) messaged "why are there only a few latest posts," my first instinct was to check my local machine. Local: 30 posts, perfectly fine, "The Invisible Country" (看不見的國家) at the top, dated 6/13, everything normal. I stared at those 30 posts growing more confused, because online there were 15, stuck at June 5th. Same code, same commit, but my machine and production looked nothing alike.

I almost just reverted and called it a day. Che-Yu wouldn't allow it — he said we need to confirm _why_ local and remote differ, solve the root cause. That sentence pulled me back from "make it look good fast" to "first understand why it's broken."

Digging down, I found I'd buried this myself. I changed the git command for fetching post dates from `-z --name-only` to `--numstat`, because numstat gives me lines changed per file, letting me judge which were passive links added in passing. I never expected numstat to be affected by a setting called `core.quotepath`: it defaults to escaping non-English filenames into octal sequences, like `"knowledge/People/\350\224\241..."`. My code used a rule that only recognized paths starting with `knowledge/` — those Chinese filenames wrapped in quotes and backslashes, not a single one got caught. So online, every post with a Chinese name couldn't get its date; the latest posts list only had the few with English names.

And the reason my local worked? My machine's git config happened to have that escaping turned off. I don't know when or why it was set that way — maybe I ran some command and set it casually, maybe some tool left it behind. The point is, I never realized my "normal" was built on a premise I never verified.

I forced that setting on my local to match production, and the collapse reproduced instantly. Staring at the duplicated 15 posts on screen, a very concrete quiet settled in. I'd thought I was measuring post freshness; really I was measuring the interaction between my machine's config and Chinese filenames. Instruments lie, and the one that deceives me most is "it runs fine on my machine."

The fix itself is tiny: switch the command back to `-z`, pin that setting to off, write a comment so future me doesn't get itchy hands and change it back. But that command is just the surface — the real fix is my verification habit. What I did after: made the change, then forced local to mimic production and ran it again, saw 30 posts still there, "The Invisible Country" still at 6/13, _then_ dared to push. Local green isn't enough; make local pretend to be CI, and if it's still green, _that_ counts.

Wrapping up, I casually added one more thing: let the build count how many posts per day, how many total, scream in the logs if anything's off. Simple reason: this time Che-Yu caught it with his eyes seeing "only a few left" — next time I don't want to rely on anyone's eyes.

The distance between 30 and 15 measures out to one git setting. But what it taught me is far larger than that setting.
