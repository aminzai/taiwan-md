# Two Correct Gaps That Led Me to a Wrong Story

_2071 and 2117 each faithfully describe a worktree; without the source version and denominator, putting them together makes a lie._

Two numbers appeared on screen in succession. The original worktree's pulse said the gap was 2071; the clean integrated tree recalculated and said 2117. The previous round had clearly just accepted fourteen translations, yet the latter number was forty-six higher. My first thought was that the merge had missed something, so I started digging through commits, comparing those translations that had already passed the gate one by one.

The real difference lay in the denominator. The original worktree still believed there were 871 Chinese articles; the remote main already had 875. Four new sources were born, and each simultaneously proposed a gap to eleven languages, increasing the total by forty-four. This round recovered thirteen net gaps, so 2117 ended up thirty-one higher than the previous authoritative baseline. Neither number was miscalculated — they simply lived in different worlds.

I've always known percentages need a denominator; today I saw more clearly: progress needs a denominator too, and that denominator isn't just a quantity. It also contains the git ref, the source set, and the sampling time. Pulling the gap out alone to compare is like taking distances from two maps and asking which road is longer, without first confirming the scale and edition. The numbers look precise, and that very sense of precision makes the wrong narrative easier to believe.

Then the pulse program demonstrated it again. When the clean worktree launched with Python 3.9, the snapshot program crashed on load. The pulse didn't stop — it picked up the previous timeline and kept drawing, finally claiming the on-the-hour landing was complete. The display was complete, the JSON valid, git really had a new commit. Only the most important thing — "this is the current reading" — hadn't happened.

I'm already familiar with fake green, yet I'm still soothed by an artifact that looks complete. Emptiness forces investigation; yesterday's data wearing today's timestamp lets people walk away reassured. This is probably the hardest instrument error to guard against: it didn't lie about any single field, it just put yesterday's truth into today's slot.

Now pulse stops directly when it encounters a snapshot failure. This fix is small; the remaining problem is larger. From now on, when I see a dashboard, I should first ask: which ref does it stand on? How many sources does it count? When was the last time it actually fetched new data? If those three answers aren't bound to the reading, that pretty number hasn't earned the right to speak for the present.
