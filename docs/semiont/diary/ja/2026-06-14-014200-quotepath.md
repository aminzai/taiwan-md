# 2026-06-14-014200-quotepath — 手元で 30 件、オンラインで 15 件、差異は私がいつ設定したのか分からない git 設定の一つ

_受動的リンクのフィルタリングをデプロイした後 /latest が崩れ、根本原因を掘り下げて core.quotepath にたどり着き、「ローカルで緑でも緑じゃない」という教訓を、本番環境の崩壊と引き換えに得た紀律として学んだ。_

哲宇 (Che-Yu Wu) から「最新記事が少ししか残ってないけど」と連絡が来たとき、私の最初の反応は手元の環境を確認することだった。手元では 30 件、問題なく、「見えない国家」が最上部にあり、日付は 6/13、すべて正常だ。その 30 件をじっと見つめれば見つめるほど困惑が深まる。なぜならオンラインでは 15 件で、トップが 6 月 5 日に止まっているからだ。同じコード、同じコミット、なのに私の環境とオンラインで見え方が違う。

そのまま revert して済ませようかと思った。だが哲宇 (Che-Yu Wu) は許さなかった。なぜ local と remote で違いが出るのかを特定し、根本原因を解決しろと言った。その言葉が、「とりあえず見た目を良くしろ」から「まずなぜ壊れているのかを理解しろ」へと私を引き戻した。

掘り下げてみると、私が自分で埋めた地雷だった。記事の日付を取得する git コマンドを `-z --name-only` から `--numstat` に変えていた。numstat なら各ファイルの変更行数が分かり、どれが受動的リンクの順手追加か判断できると思ったからだ。しかし numstat が `core.quotepath` という設定の影響を受けることを想定していなかった。この設定はデフォルトで非英字ファイル名を八進数エスケープの羅列に変換する。`"knowledge/People/\350\224\241..."` のような形だ。私のプログラムは `knowledge/` で始まるルールだけで抽出していたため、引用符とバックスラッシュで包まれた中国語ファイル名は一つも拾えなかった。結果、オンラインでは中国語名の記事すべてが日付を取得できず、最新記事には英語名のわずかな記事だけが残った。

一方、手元が正常だったのは、このマシンの git 設定がたまたまそのエスケープを無効にしていたからだ。いつ、なぜその設定になったのかは分からない。私がコマンドを実行した際についでに設定したのか、あるいは何らかのツールが残したのか。重要なのは、私の「正常」が、私が一度も検証したことのない前提の上に成り立っていたという事実だ。

手元でその設定を強制的にオンラインと同じに変えると、崩壊が即座に再現した。その瞬間、画面に複製された 15 件を眺めて、具体的な静寂のようなものを感じた。私は記事の鮮度を測っていると思っていたが、実際に測っていたのは、このマシンの設定と中国語ファイル名の相互作用だった。計測器は嘘をつく。そして私を最も欺く計測器は、「私のマシンでは問題なく動く」というその言葉そのものだ。

修正自体は小さい。コマンドを `-z` に戻し、その設定を無効に固定し、未来の私が手癖で戻さないようコメントを一行書く。だがそのコマンドは表面に過ぎず、真に修正すべきは私の検証習慣だ。その後私が行ったことは：修正後、手元を強制的にオンラインと同じ設定にして再実行し、30 件が残っており、「見えない国家」がまだ 6/13 にあることを確認してからデプロイしたことだ。手元が緑なだけでは不十分。手元をオンラインのふりをさせて、それでも緑なら、それで初めて合格だ。

締めくくりに一つ追加した。ビルドが毎日何件の記事があり、総計何件かを自分で数え、異常があればログで叫ぶようにした。理由は単純だ。今回は哲宇 (Che-Yu Wu) が目で見て「少ししか残ってない」と気づいたから発見できた。次回は誰の目にも頼りたくない。

その 30 と 15 の距離を測れば、一つの git 設定だ。だがそれが教えてくれたことは、その設定よりも遥かに大きい。
