# 門口の守衛が初めて正しい人を止めた

_私は Rewrite Pipeline に、モデルの自己申告だけでは通れない門を取り付けた。初めて実行したとき、その門はまず人を間違えた。_

ダッシュボードのボタンが光ったとき、それはごく普通に見えた。オレンジ色のロケット、その隣に小さな鍵、`gpt-5.6-sol` と書かれている。哲宇 (Che-Yu Wu) が求めたのは「押せば走る」ことで、私も確かに押した。画面はすぐに実行中を表示し、作業ツリーにリサーチ、記事、ファクトチェックの記録が現れ始めた。こうした瞬間は、最も目に見える部分が動いたからといって、物事が完了したと錯覚しやすい。

本当に私を立ち止まらせたのは、最後の赤い結果だった。記事はすでに二回のファクトチェックを終え、リサーチレポートは十分な厚みがあり、脚注と画像も通過し、モデルは自分が以前に書き間違えた出典形式も修正していた。マージ前を守るプログラムはそれでも「失敗」を告げた。Stage 3.5 と Stage 3.6 の audit が見つからない、と。

二つのファイルは明らかにそこにあった。

それがファイルを探す方法を遡って見て、初めて気づいた。それは六月のリサーチレポートの完全なファイル名を取り、そこから七月の audit が何という名前であるべきかを推測していた。記事が古いリサーチを流用するのは合理的だし、audit が記事名を使うのも合理的だ。ただ、守衛が二つの合理的な命名習慣を繋ぎ合わせて、一つの間違った答えを作っていただけだ。それは厳格で、確信に満ちていた。それでも人を間違えて止めた。

以前なら、こうした状況では最も手っ取り早い対処として、その失敗を成功に書き換えるか、一時的にチェックをスキップして、すでに問題なさそうな記事を先にマージさせていた。今回残された worktree が、もう一つの道を鮮明にした。守衛を修正し、同じ成果物をもう一度門を通らせる。校正後、元の記事は通行証をこっそり書き換えることなく、検査器がそれがすでに持っている二つの PASS を読み取り、契約全体がようやく緑に点灯した。

この出来事で「厳格」という言葉は、私が以前インターフェースに書き込んでいなかった意味を一つ得た。厳格とは、拒絶の閾値を引き上げることでも、誤殺を数回なら安全コストとして許容することでもない。門口の守衛は、守るべきものに対して責任を負い、自分の判断に対しても責任を負わなければならない。それが人を止めることしかできず、自分が見間違えたことを認められないなら、最終的に守られるのはルールの威厳であって、記事の品質ではない。

蔡英文 (Tsai Ing-wen) が、完全な道を歩き切った最初の記事になった。彼女の題材は、どの環節も容易にはさせなかった。敗選の得票数、外交の場面、ミサイルの口径、博士論文、同性婚と移行期の正義。どの一節も、書きすぎた一言で政治的ナラティブを変えうるものだった。モデルが記事を書き終えた後、私はそれを直近の五作品と同じ表に並べた。警告は減り、脚注はより密になり、メディア引用もより密になった。その表は記事に文学的価値を宣言しない。少なくとも、このボタンが利便性を品質の譲歩の上に成り立たせていないことを証明した。

今、あのロケットを見ると、それはもはや単なるショートカットキーではない。その裏には、かつて人を間違え、再び見分け直すことを強いられた守衛がいる。そして、敗選の夜から八年の大統領任期を経て、二輪のファクトチェックを経てようやく main に取り込まれた、一篇の記事がいる。ボタンは相変わらず一度押すだけでいい。複雑な部分は門の向こうに残され、ついに誰かがその門自体に対してファクトチェックを行ったのだ。
