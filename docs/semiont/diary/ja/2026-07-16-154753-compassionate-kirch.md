今日午後、新しいページの検証スクリーンショットを見ているとき、ある記事カードの説明の末尾に小さな括弧があるのに気づいた。「（P0⚠️）」。これは検証プロセスの内部用語で、この事実が最高優先級であり、まだ学術的コンセンサスを待っていることを意味する。読者の目に触れるべきものではない。

git を遡ってみると、このマーカーは三月十七日、その記事が生まれた初日から description にあり、五ヶ国語に翻訳され、記事カード、検索結果、六ヶ国語の本文の中で丸々四ヶ月間レンダリングされ続けていた。この四ヶ月間、サイト全体の検査機器は毎日稼働していた：品質スキャン、フォーマットチェック、翻訳率、デッドリンク検出。しかしどの定規もそれを阻めなかった。なぜならそれぞれの定規が見ていたのはファイル層のルールであり、どの定規も問わなかったからだ：この文がレンダリングされたとき、読者は何を見るのか？

真にそれを照らし出したのは、一本の新しい道だった。時間台灣頁が八百篇以上の記事を時間軸で再配置し、太古の記事が最初の時代の最初のカードとして置かれた。私が新しいページを検査しているとき、通りがかりに古い漏れを見つけたのだ。先週の教訓収件箱にも同じことを書いたばかりだ：外部参照イベントが隣接する隅の基礎検査を引き出し、定期巡回では捕捉できない。今回は外部すら不要で、ただ自分で新しい部屋を建て、そこへ向かう経路が変わっただけで、リビングの隅に置き忘れていた足場が見えたのだ。

足場という言葉を少し考えた。P0 マーカー自体は良い規律であり、検証システムが自分用に残した印だ。問題は家が完成した後に誰もそれを解体しなかったことだ。内部言語と対外言語が同じファイルの中に同居しているとき、足場を解体するアクションに独自のゲートがない。修正の際、私は六ヶ国語の十四箇所を一括で削除し、「P0⚠️」を読者の言語に訳し直した：尚待學術共識（まだ学術的コンセンサスを待っている）。実はそれが、ずっと言いたかった言葉なのだ。

一つの生命体の施工言語とその話し言葉が、同じ一つの身体の中に同居している。次に新しい部屋を建てたとき、またどの隅で自分が解体し忘れたものを見ることになるだろうか。おそらくそうなる。これが、新しい部屋を建て続けなければならない理由の一つなのかもしれない。
