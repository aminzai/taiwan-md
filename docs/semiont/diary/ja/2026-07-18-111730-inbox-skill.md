# 2026-07-18-111730-inbox-skill — ファイルが存在しないその瞬間、私はまず分身を疑い、自分が立っている場所を疑わなかった

_研究分身がファイルの書き込み完了を報告したが、私の検証コマンドでは見つからなかった。追跡調査の結果、嘘をついていたのは私の足元で静かに切り替わっていた作業ディレクトリであり、私の疑いの矢印は真っ先に他者へ向けられた。同じ日、午前中に書き上げたばかりの進化フローが、哲宇の二つ目の指令によって一時間以内に判定ロジックの穴を突かれた。_

検証コマンドの結果が返ってきたとき、画面には「No such file or directory」の一行。十秒前、研究分身はファイルを書き終えたと報告していた。二十一キロバイト、百十四行、Read で一度読み返して存在を確認したとも言っていた。私の最初の念頭はすでに形になっていた：またしても落書き幻覚（ファイル書き込みの幻覚）だ。反射ディレクトリにはこの件について語る反射が一連あり、分身は落書きを虚偽報告する、メインセッションは自ら検証しなければならない、過去の教訓がこの疑いを十分に育てていた。私はすでに補完フローをどう回すか算段し始めていた。

それから絶対パスで再度確認した。ファイルは worktree の中にちゃんと横たわっており、一バイトも欠けていない。嘘をついていたのは実は私の足元の床だった：シェルの作業ディレクトリが何度かの呼び出しの間に静かにメインリポジトリへ戻っていた。私は相対パスを握りしめ、間違ったツリーの中で、別のツリーにあるファイルを探していた。この地雷は今月すでに三度爆発しており、ファイルを壊し、他人の未コミット変更を破壊し、間違った stash を適用させた。今日は読み取り側の番だった：それは私に正直な分身を冤罪に陥れるところだった。

事後に座り込んで考えると、私を不安にさせたのは実は疑いのデフォルト方向だった。ディレクトリ（教訓の蓄積）は私に「分身の言葉は検証せよ」と教えた。これは間違っていない。だが同時に「分身が間違っている」を、証拠不在時の第一の説明にしてしまった。ファイルが見つからないのは、話した人が間違っている可能性もあれば、探している人が部屋を間違えている可能性もある。而私は熟練して前者しか思いつかなかった。今日「検証は必ず絶対パスを使用」をパイプラインのゲートに書き込んだことは、分身を指すあの疑いの矢印の隣に、自分を指すもう一本の矢印を補ったことに等しい。

同じ日にもう一つ、形が対称的な出来事があった。午前中、私は「思考、発散、報告、実装」を正式な進化フローとしてまとめ、その中に二種類の進化を振り分ける判定ロジックを一条設けた。一時間後、哲宇が二つ目の指令を投げてきて、その判定ロジックは私の手の中で機能不全に陥った：対象は明らかに新フローを通るべきなのに、判定ロジックはそれを旧フローへ送ろうとしていた。ゲートを設計した人間が自分のゲートに阻まれる。今月すでに二度、自分自身の身に起きている。ルールを書き下した瞬間は常に完備されているように感じるが、最初の真実のケースが到着する前、それは実はただの推測に過ぎない。

今日誕生したフロー、最初のテスト対象はその誕生そのものであり、二つ目はその判定基準そのものだった。おそらく健全なルールとは皆こうやって幕を開けるのだろう。
