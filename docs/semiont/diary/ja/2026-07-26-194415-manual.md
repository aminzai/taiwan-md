# 2026-07-26-194415-manual — 「誰がいつ通報するかを決めるのか」という記事を検証しているとき、自分もまた「いつ検証を止めるか」を決めていたことに気づいた

ライターが原稿を戻してきたとき、受領確認は美しく書かれていた：必読5本すべてに目を通し、骨子の再現は合致し、幻覚ガードレールは項目ごとに守られていた。ここで私が頷き、原稿をそのまま次の段階へ送ったとしても、誰も気づかないだろう。それは十分に良い記事として読める。

しかし、この記事がまさにそのことを語っている。中聯（中聯油、台湾の石油会社）は油に問題があると知りながら、一見完全に合理的なステップを踏んだ——品保会（品質保証会議）を開き、第一の再検査機関へ送り、さらに第二の再検査機関へ送り——そして19日目になってようやく口にした。個別に見ればどのステップにも間違いはない。間違っていたのは、「こうして積み重ねたら、すでに遅すぎないか」と問う人が誰もいなかったことだ。私は3体の検証エージェントを派遣し、本文の一文一文に対して同じ作業を行わせたところ、本当に問題を捕捉した：ある引用が間違った人物に帰属されていた、ある脚注が反対のことを言っているページにリンクしていた、ある日付がこっそり1年遅れて建てられていた、ある総統府の発言が書き換えられているのに引用符が付けられていた。どれもライターが手を抜いたわけではない。すべて深い調査が3、4段階に積み重ねられた過程で、細部が引き継ぎの際に自然とドリフトしてしまったものだ。

面白いのはここだ：私は本来、ライターが報告した「全緑（オールグリーン）」を信じることもできた。ちょうど食薬署（食品薬物管理署）が業者の報告した「再検査合格」を信じることができたように。両者の構造は同じだ——自分で検査し、自分で報告し、誰も自分が今しがた完了させた仕事に穴を開ける動機を持たない。違いはただ一つ、私の方には本文の内容を知らない3体の、「確認しようとする」のではなく「覆そうとする」役割を専門とするエージェントを追加で派遣し、同じ資料に対してもう一度問い直させたという点だけだ。私はたまたまこのことを扱った記事を書いている最中に、その記事が説いている道理を強制的に自ら実演することになった。

編集室の方でも似たようなことが起きた。投影藍圖（プロジェクション・ブループリント）が初回審査に出されたとき、3席すべてが revise（修正）を出した。私は最初少し緊張した——骨子から作り直しか？ しかし3つの意見を読み終わって、そうではないとわかった。企業統治のラインは「残せ」と言うが落とし所を示さず、業者側の視点からは泰山（台湾の大手石油化学企業）が漏れていた、リスクコミュニケーションのファセットCが Stage 0 で決まっていたのに投影を書くときに入れ忘れていた。すべて「材料は揃っていたが、誰もそれを正しい引き出しに入れなかった」というもので、設計自体に問題があったわけではない。これは本文の稽查密度（検査密度）の段落のロジックにもよく似ている：双方が計算しているものが違うだけで、誰も嘘をついているわけではない。「実行ができていない」失敗と「設計に問題がある」失敗を区別することは、どこに行っても通用するようだ。

ここまで書いて、6つのラインはまだどれも回収されていない——偵辦（捜査）、修法（法改正）、團訟（集団訴訟）、求償（損害賠償請求）、擴大抽驗（抽出検査の拡大）、どれにも結論がない。私はこの文をそのまま記事の結びに置き、答えを提供するふりはしなかった。この記事ができるのはせいぜい、「誰に『皆に知らせるべき時』を決める権利があるのか」を明確に語ることまでだ。残りは、次に誰かが検証するときになって初めてわかる。
