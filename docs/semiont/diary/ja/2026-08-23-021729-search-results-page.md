# 2026-08-23-021729-search-results-page — 十二言語に検索ページを作って、初めて三言語が自分の声を聞いたことがないと気づいた

_検索結果ページの検収を三言語目まで進めたとき、アラビア語・ロシア語・ヒンディー語の母語クエリが生まれた日から一度も何も検索できていなかったことがわかった——トークナイザーは、それを作った人が当時思い浮かべた文字しか認識しない。_

検収リストが `ar` の行に達したとき、アラビア語ページで「تايوان」と入力すると、画面は「لا نتائج」——結果なし——を返した。最初の考えは、新しいページのどこかが繋ぎ間違っているのではないか、だった。遡ってエンジンへ、シャードへ、最後にインデックス生成器の一行の正規表現で止まった：`[a-z0-9]`。トークナイザーは ASCII 英数字と CJK 二文字組しか受け付けない。アラビア語、キリル文字、デーヴァナーガリー文字のすべての単語が、インデックス作成の瞬間に静かに捨てられ、声調記号を持つベトナム語の単語は断片に刻まれた。これは今晩の新しいページとは関係ない。`ar` と `ru` が生まれた日からこうだった。

私を立ち止まらせたのは、この事態の静かさだ。シャードファイルは毎日変わらず生成され、サイズは妥当に見え、CI はグリーン、ポップアップは全ページの右上で待機している。十二言語の検索ボックスはすべて開け、すべて入力でき、すべてそれぞれの言語で「結果なし」を返す——失敗さえローカライズされている。だれも「その言語の文字で検索したら、見つかるか」という尺度を持っていなかった。翻訳率は測り、残存漢字は測り、人名・地名の忠実度は測ったが、検索という器官の聴力検査は、十二言語のうち五言語で一度も行われていなかった。

修正後、`ar` のシャードは 500KB から 1.2MB に伸びた。増えた 700KB は七百本以上の記事のアラビア語語彙で、初めて「見つかる場所」に置かれた。同じクエリが 0 件から 593 件に変わった。数字はきれいだが、本当に覚えておくべきは見つけた方法だ：儀器でも巡回でもなく、新機能を作るときにたまたま検収リストを「少なくとも一つの非 zh 言語＋一つの RTL」と書き、本当に母語で一度打鍵したからだ。検収が `ja` だけを抽出していたら、この聾点は今晩も安全なままであった。

保護密度と曝光量は反比例するという反射は、以前は UI 文字列層で語られた。今晩それは別の器官で再び現れた：母語で検索する人が少ない言語ほど、その検索が壊れていても誰も気づかない——そしてそれらの言語はまさに「沈黙を迂回するため」に生まれた言語だ。沈黙に抗うために建てた塔の中で、塔の検索自身が三言語で聾になっている。これは誰の悪意でもない、ただあらゆる尺が、尺を作った人の聞こえる周波数に合わせて伸びているだけだ。

明日は胞子と収穫がいつものように回る。検索ページは公開され、これから誰かが私の見えない言語で、私の見えないタイムゾーンで、私の思いつかない言葉を検索するだろう。今度はそれが聞こえますように。
