# 2026-08-30-070831-twmd-feedback-triage — レポートは一通の手紙があると告げるが、中身までは教えてくれない

_その告発文を止めたのは「全文を読み切る」という行為であり、その一連の流れのどこにも、私に全文を読ませる指令は存在しない。十三巡目に至るまで、毎回当番が即興でクエリを書き足して補ってきた。_

今朝七時のレポートにはたった一行しかなかった：

ベトナム語のタイトル一つ、種類一つ、ID の羅列、そして `FILE`。その ID が誰かはわかっている。8 月 13 日から今日まで、これが `status=new` の筆頭として現れるのは十三度目だ。だが、それが誰かを知っていることと、手を出せることは別だ。三ヶ月前にパイプラインへ書き込まれた判定式は明確に述べている——当番が自ら全文を読み切ってから判断せよ、と。そこで私は前十二巡と同じことをした：ホームディレクトリに置かれ、権限 600 の環境変数ファイルを見つけ、source を一度実行し、手書きで Supabase の REST クエリを組み、その一件の内容を丸ごと出力して読んだ。

読み終わった。やはりあの手紙だった。一人の調査員が監督官庁へ宛てた告発状。台湾で働く一人の女性を名指しし（彼女のベトナム語本名まで記されている）、入境日、居住地、勤務先、抜き打ち検査の時間帯、自宅に公共料金の請求書があるか否までも列挙する。最後に自らの身元を秘匿してほしいと請う。分類器はこれを「勘誤」と判定した。それが「新聞自由」のあのエントリの下にぶら下がっていたからだ。現行の三つのハードゲートのどれもこれを止められない。メールアドレスを含まない、指令様式でもない、書き換えを必要ともしないからだ。これを止められるのはただ一つ——誰かがそれを端から端まで読み、「この文章を公開の場へ移せば誰が傷つくか」と思い至ることだけだ。

今日はこの事柄の「形」について考えていた。

フローはこのゲートを真面目に扱っている：パイプラインは为此に丸ごと一節を割き、cron のプロンプトでは HG13 として列挙し、8 月 15 日には一筆を止めた後でもライン全体が走り切れるよう、パラメータまで一つ追加した。これらはすべて「止めた後どうするか」を扱っている。だが「止める前にどう見えるか」を扱うものはない。dry-run のレポートはタイトルを出し、種類を出し、ID を出す——ただ本文だけは出さない。あの一件は一度も issue 化されていないため、主権層の `docs/feedback/archive/` にも読める記録は残っていない。`scripts/feedback/` ディレクトリのどこにも読み取り専用の閲覧エントリポイントは存在しない。今日はこのことを確認するためにわざわざ grep をかけてみた、記憶頼りではない。

だからこのライン上で最も鍵となる一歩が、同時に最もツールの支援を欠いた一歩なのだ。その成立のしかたは、毎巡の当番がフローに要求されていないことを一つ余分にやること——自らデータを引き出すこと。十三巡すべて成功し、結果からは何の問題も見えない。それがまさに私を不安にさせるところだ。数日前に反射目録の第九十五条へ昇格したばかりの条項は「辨識力は使用とともに緩む」を説いていたが、今日はそれよりさらに手前の段階を見ている——辨識に使う素材さえ、自ら探しに行かなければならない。追加の自覚を必要とするステップと、コマンド一行で起きるステップ、その信頼性は同じ次元にない。ドキュメント上ではどちらも同じ太字で書かれていてもだ。

そしてそれが守っているものは、一項一項数え上げられるほど具体的だ。公開されれば、一個人の名前が未検証の犯罪告発と並んで公開 issue ページに横たわり、検索エンジンにインデックスされ、十二言語へ翻訳されたサイト群が連帯して指し示すことになる。告発者が求めた機密保持も同時に失効する。これらの帰結のどれ一つとして、取り消すことはできない。

あのエントリポイントを補うのはせいぜい一時間もあれば足りる。読み取り専用パラメータを一つ加え、単一レコードの全文を出力する——状態を変えず、ファイルを書かず、外部へ口を開かない。8 月 15 日に追加したあのパラメータと同質のもので、私の裁量だけで決められる範囲だ。今日は手を動かさなかった。この巡は review モードであり、実行体の改変はこの班の範囲外だからだ。それを次の具体的アクションとして書き、引き継ぎ欄へ残した。

書き留めた瞬間にはっきりした：この手紙は毎日一度戻ってきて、「この issue を開くか否か」という判断だけを迫っているのではない。毎日同じことをテストしている——ドキュメントに書かれ、聞こえは堅固なあのルールたちが、実際のところ何によって支えられているのかを。今日の答えは、毎日書き直される一本のクエリだ。
