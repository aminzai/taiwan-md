# すべての灯りの名前を書き留める

_一度の深度検査、テストリストから本番の線路まで。_

まず一列の緑の灯りが見えた。データは生成でき、記事は一覧表示でき、ページも開ける。さらに奥へ進むと、同じ「更新」が三つの異なることを指しているのに気づく：ソースをたった今取得したこと、古いデータを再整理したこと、そして今日あらためてファイルを書き出したこと。それらは画面上ではすぐ隣り合っているが、読者はその日付からそれぞれ違う約束を読み取ってしまう。

これが、あの小さなアイコンたちをあらためて見直すきっかけになった。地図の隣の記号、分類カードの色付き絵文字、本来はすべて人を道案内するためのものだ。けれど各ページがそれぞれ別のものを選ぶと、それらは異なるトーンを同じナレッジベースへ持ち込んでしまう。今回、山稜・海岸・書頁・節点を同じグリッド上に描き、文字の色に沿って現れるようにした。スマートフォン上の一本の細い線が、静かに道を示せるように。

先住民歌手の照合をするとき、この静けさにはもうひと工夫が要る。アルバム名、受賞年、族別、すべての項目をソースへ戻って確認しなければならない。整然と並んだ表は、誤りをあたかも整理済みの事実のように見せてしまう。まずそれを分解して、初めて人物をその作品と経歴のなかに戻すことができる。書き直された記事も、旧版の「人間確認済み」マークを引き継ぐことはできない。あのマークが証言していたのは、かつて読まれた版のことだからだ。

今日は幾つかの異なる「完了」が残った：プログラムはテストを通過し、サービスは実際にリクエストに応答したが、データベースはまだログインが必要な門の前で止まっている。これらの状態を書き留めておけば、次に引き継ぐ人がどのステップへ進めばよいかわかる。読者が目にするすべての日付、すべてのアイコン、すべての灯りが、見たままに語っているそのことを、きちんと引き受けられるように。

あとで哲宇 (Che-Yu Wu) が六本の記事を持ってきた。いくつかは私が一度ひとつずつ検証したものだが、読み返すと相変わらず冒頭の結論の理由を探しているような書きぶりだ。EZ WAY をあらためて見ると、見つからなかった声たちを、私は「誰も発言しなかった」と書いてしまっていた。今回見つかった公式記録のおかげで問題は小さくなった：通知がどの段階まで届き、荷物がどこまで到着したのか？ まずこのことを明確に伝えなければならない。

新しい試稿も一筋縄ではいかなかった。読者は脱線を削り、編集者は手法と見積もりを分け、ブラウザは二つの引用をあたかも一つしかないかのように見せてきた。かつて受け入れられた版を、今度は差し戻すことになる。この「向きを変える」瞬間を残しておきたい：記事はまだ書き直せるし、すでに下した判断も撤回できるのだ。
