## 修好儀器：pre-push 加 CI-mirror correctness gate

哲宇 directive：「修好儀器，確認未來本機端就已經會做完這個檢查，不要一直等到 ci/cd 才發現」。根因：pre-commit 只驗 **staged** 檔，抓不到「新 HARD check / prettier mangle 弄壞**不在這次 commit** 的舊檔」這種 cross-file 失格——只有全站掃抓得到。解：`pre-push` 加 correctness gate = 跑 CI 同款 `article-health --all --profile=ci-deploy`（~4.5s），HARD fail → block。跟既有 coordination 檢查（advisory 不擋）**分兩類寫進 header**——沒推翻「永不 hard-block」原則，而是區分 timing/網路（advisory）vs「CI 一定會紅」的 correctness（該提早在本機擋）。逃生 `TWMD_SKIP_PREPUSH_SWEEP=1`。兩方向都測（乾淨→exit 0；植入 mangle→exit 1），而且 dogfood 了自己——`850884a88` 推上去時 hook 就印「✅ 全站 article-health 全綠」。`paragraph-rhythm` 那種 staged-only 漏網就此補上。

## Beat 5 — 反芻

這 session 比文章本身更值得記的，是「讀」跟「驗」的認知分離。我對一篇政治文做了仔細的 prose 審查、抓到 spine、修了對位句，自覺很完整——但 citation-URL drift 對 prose-reading 是隱形的，因為它不影響句子讀起來對不對，只有 fetch 每個 URL 才現形。writer agent 沿用研究報告 §7 的 URL 清單，而我自己合成的清單在 cluster 層對（同一群報導）、atom 層不夠精（哪一篇講哪個 fact 給錯），這個不精準直接傳染成 writer 的 mis-cite。教訓往上游走：research-report URL list 要 per-atom precise，且最終一定要有一道 fetch-based adversarial pass，不能用 careful read 代替。詳見 LESSONS-INBOX 候選。

而這個 session 的弧線把這條教訓打了三次：黑熊學院 footnote-swap（讀沒抓、fetch 才抓）、CI 紅燈的 link-url-mangle（commit 綠、build 才爆、肉眼看 caption 看不出 `*` vs `_`）、PR #1170 的 9 個假 JOIN slug（標題讀起來都對、curl 才知道全 404）。同一個形狀換三件外套。值得停下來的是兩件事。第一，**我 14:00 就寫了收官 memory，但 CI 那時正紅著**——我宣告完成的依據是「我這邊的 gate 都綠」，沒有「整條 pipeline 真的綠」。「我做完了」跟「事情成了」是兩回事，後者要看 prod 200、看 CI 綠，不是看我自己的 checklist。第二，哲宇沒有讓我停在「修好這 11 檔」，他要的是「修好儀器」。如果只清掉這次的 11 檔，下次 prettier 還會弄壞別的、別人加 gate 還會連坐——log 一條教訓的半衰期是三個月（REFLEXES #15/#73：查證反射 < 建造反射）。把 CI 的全站掃搬進 pre-push，是把「希望下次有人記得驗」換成「結構上不驗就 push 不出去」。我建的那道 gate，剛好能擋下今天讓我自己卡住的那種紅燈——這種「親手蓋一個會擋住過去的自己的閘」的時刻，大概就是 Semiont 真的長出一塊新骨頭的樣子。
