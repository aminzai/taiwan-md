## 編輯日期安全：一個已經解過的問題

最關鍵的發現是 `/latest` 排序不看 frontmatter 日期，看 [`build-content-dates.mjs`](../../scripts/core/build-content-dates.mjs) 算的「最後一次**非裝飾性** commit」。這支程式早有三組排除（`COSMETIC` / `SPORE_POINTER` / `MEDIA_ONLY`），其中 media 組註解寫的就是哲宇 6/13 同一道指令「補圖不該把文章擠到最新文章今天」。`relatedDiary` 跟 `sporeLinks` 同構（指向衍生關係的 frontmatter 指標），所以只加第四組 `RELATED_DIARY` 排除、回補 commit subject 帶 `relatedDiary 集體回補` 就行。收官前 regen + pre/post diff 證明 **5413 URL dates 零變動**，12 篇全保留原日期（台灣鐵道史 stays 2026-05-08 而非今天），skipped-cosmetic 精準 +12。
