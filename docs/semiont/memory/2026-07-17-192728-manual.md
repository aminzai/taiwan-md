## 偵破：三個互相掩護的根因

用不濾 UA 的 CF 全量查詢對 route 表交叉對賬（舊工具 `analyze-crawler-404.py` 只看 10 個 bot allowlist，人類結構性看不見）。查明主因是 `SEO.astro` 的 hreflang 用字串拼接換語言前綴，但同篇文章的 slug 各語言本就不同（李珠珢：en 是 lee-ju-eun、ja 是 lee-ju-eun-singer）——全站 5,031 篇吐出 13,014 條指向 404 的 alternate（99.8% 頁面），實際 404 流量至少 28% 直接命中這個自吐集合。爬蟲不是亂猜，是忠實跟隨我們發的死連結；「crawler 掃舊 URL」的量對了、因果反了。第二根因：404 頁的 `page_404` 追蹤事件因 block scope 錯誤在 payload 求值時丟 ReferenceError、被靜默 catch 吞掉，無聲死了三個月——期間還有 session 替它註冊了四個從沒收過資料的 GA4 維度（`instrumentation-audit` 查存在不查發射，REFLEXES #82 教科書案例）。第三根因：語言註冊表 `fromZh` 被 en-slug 別名 last-write-wins 蓋掉原生 slug，連可見的語言切換器都在吐死鏈。附帶平反一樁三個月冤案：`<strange-chars>` 是 CF 對壞編碼的正規化佔位符，四月報告把儀器自己的佔位符當站上模板 bug 在追。完整證據鏈在 [reports/404-root-cause-2026-07-17.md](../../reports/404-root-cause-2026-07-17.md)。

## 實作：三刀根治＋五路分身

根源三刀親手修（`a06b89d25`：hreflang 走註冊表、fromZh first-wins、page_404 復活），dev 上六語 slug 全分歧的李珠珢三個語言版本吐出完全一致的 7 條叢集、逐條 curl 全 200。過程踩到 Astro expression scanner 把 `Record<string,...>` 泛型當 JSX tag 的地雷（esbuild 連環炸），解法是把邏輯搬進 frontmatter。之後切 Fable 總指揮、五路 Sonnet 分身平行實作：monitor-404 監測儀器（resolution-based 分家族、接 refresh-data 與 alerts，`6ec56837c`）、資料驅動 redirect 產生器（`8b5851645`）、22 縣市 topo 檔補齊（頁面公告了 22 縣市卻只放 6 檔，`a03ca7f6f`）、404 頁 .md 救援（LLM agent 解析相對 wikilink 的請求導向 raw 視圖）、URL 契約對賬 gate（`c69c1e319`，對修復前舊 dist 一跑抓到 18,406 條死 alternate，sitemap 0 死——唯一有對賬機制的公告層唯一乾淨）。認知層同步：CONSCIOUSNESS 那條 🟠 改成已查明因果、UNKNOWNS 立 EXP-2026-07-17-G（D+21 404 率 ≤8%，機械到期）、LESSONS 入庫「對外公告的機器 URL 契約沒有對賬閘門」。

## 多核心擦撞：分身交付物被友軍砲火銷毀

實作中段，每小時 fire 的 rewrite-daily cron 在共用樹上甦醒、撞上 30 天前的舊 stash，`reset --hard` + `rm -rf` 九檔「清理」時把 S1/S2 分身剛落地幾分鐘的活交付物誤判成 stash 污染整批銷毀（它自己的 memory `c811d1e8e` 誠實記錄了全程）。復原走分身 context 重出（約 40 分），後續它的 pull-rebase 又停格在衝突上，我的 pathspec commit 落在停格的 detached HEAD，tracked 檔改動被 lint-staged 的 stash 圈掉，最後以 `0c1ef7426` 收攏補齊並逐項 grep HEAD 驗證完整性。教訓已補進 LESSONS `cron-fire-meets-dormant-stash` 的 instance（vc=2）：銷毀前驗 mtime 就能分辨 30 天舊物與 3 分鐘活物；主 session 側對策是分身工作驗完立刻 commit。
