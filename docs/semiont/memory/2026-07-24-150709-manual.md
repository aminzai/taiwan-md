## 三度撞見 git 競態

commit 過程連撞兩次跟另一個平行巴別塔 fleet session 共用 index 的問題：一次是我剛 `add` 完還沒 `commit`，對方的 commit 先落地把我的檔案掃走掛到他們的訊息底下；退回去查才發現這正是 [REFLEXES #68](../REFLEXES.md) 已經記載過的模式（vc=3 起就寫了解法是 `git commit --only`）。用上這個解法後 commit 乾淨，但 push 又卡了一次——追下去發現是 pre-push hook 在 `sh -e` 語意下，只要 `sync-translations-json.py --check` 回非零值（哪怕只是「索引暫時失衡」不是真的孤兒），整支 hook 會在自己該檢查的 grep 條件之前就先被腰斬。因為這個索引失衡是對方 session 還在寫的檔案造成的暫時狀態，不是我這次 commit 的內容問題，用了 hook 本身就寫好的逃生閥門 `TWMD_SKIP_PREPUSH_SWEEP=1` 放行，CI 仍會獨立驗證真正推上去的樹。把這次的再驗證補進 REFLEXES #68（vc=3→4），加一句「知道規則」跟「當下用上規則」是兩件事——我自己就是先用了 bare `git commit` 才踩到雷，才想起要查 canonical。
