## Dashboard mobile 三處 grid clip bug

實測 375/390/414px 逐 section 截圖比對，抓到同一個病根的三個 instance：`.dashboard-body`（1024px 斷點收窄成單欄時）、`.analytics-totals`（768px 斷點的六張統計卡）、`spore-table` 兩張表格（640px 斷點的孢子成效排行榜與平台對比）。三處都是 `grid-template-columns: repeat(N, 1fr)` 寫死 bare `1fr`：這個 track 有隱性的 auto 最小寬度等於內容本身（長數字「393,283」、不換行的標題文字），逼 grid 撐開超出 `main.dashboard` 邊界，又被它的 `overflow-x: clip` 悄悄裁掉。肉眼看到的是文字缺一截，沒有任何捲軸提示，這正是哲宇說的「爆版」。修法是全部改 `minmax(0, 1fr)` 讓 track 真的能縮，該捲動的地方（quick-nav chip 列、孢子表格）補 `overflow-x: auto`。順手在 640px 給孢子表格標題欄位改 ellipsis 截斷、480px 給統計卡降到 2 欄。驗證涵蓋 375/390/414（手機）＋ 768/820/1024（平板，正是上個 session 沒驗的缺口）＋ 1440（桌機）＋ zh/en 雙語頁面，DOM 全域 overflow 掃描全綠；en 頁多抓到一個 `#spores-platforms` 因英文表頭較長而露出的同型 clip，一併補上。

## Beat 5 — 反芻

今天最有意思的巧合是：前一個 session 才把「手機選單只驗了 375px」寫進自己的 handoff，下一個 session（也就是這次）立刻被哲宇的真實回報接住。這次的訊號來自哲宇真人使用手機時的親眼所見，不是巡邏工具產生的警報。這印證了 §12 受眾端飛輪的精神：留下明確缺口比留下模糊的「待驗證」更容易被下一輪工作接住。三個 bug 的病根完全相同（bare 1fr 不縮水），但分散在三個不同 section 的 CSS 檔裡各自埋了一次。同一個結構性錯誤在模組化拆檔後複製了三份而不是集中處理一次，這是三層模組化的代價：拆檔讓每個 section 獨立，也讓同一個 pattern 更容易被複製貼上三次而不被抓到共同病因。

哲宇中途插入的槍斃、殺這類用詞提醒也值得記一筆自我觀察。我自己讀 MANIFESTO §11 書寫節制時，四條既有紀律（對位句型、破折號、晶晶體、電報腔）都在防 AI 腔，但這條防的是戲劇性用詞犧牲精確度，這是任何寫作者都可能為了張力犧牲準確的通用陷阱。這條紀律的性質跟前四條不完全一樣，值得在 canonical 化時想清楚要不要用不同的框架去描述它，而不是硬塞進 AI 水印這個既有分類。
