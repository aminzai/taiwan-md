## #1199/#1200/#1201：三則早就修好了，只是沒人回來關

這三則是同一位讀者（帳號名「中共認知作戰前線戰地記者」）2026-07-02 三分鐘內連發的。07-03 的回覆說「knowledge/ 全站 grep 找不到，請你補 URL」，然後掛了 23 天。

三個問題本身都在 2026-07-11 的詞庫全審（`db957fec7`）修掉了：台灣側詞條原本寫「**乌**子山共和國」（簡體字＋塞拉利昂的亂碼錯譯）與「厄**乙**垂亞」（錯字），現在是「獅子山共和國」與「厄利垂亞」。也就是說讀者三則回報全部生效，只是對外失聯 23 天，是「做了不記＝沒做」的對外鏡像。

補的最後一哩是轉址：詞條改名讓讀者原本站的兩個網址死掉，加兩條 Astro inline redirect 接回去。這裡查證了一件事才動手：`config/redirects-manual.txt` 產生的 `public/_redirects` 在 GitHub Pages **不被支援**（astro.config 註解自己寫了），有效的只有 astro `redirects:` 的 meta-refresh stub。寫進 manual 檔會是一條靜默無效的轉址，剛好就是 proxy signal 那個病。

## PR #1247：merge 了，但政治那段是我改最多的地方

腳註先抽三則逐字驗（中央社、風傳媒 QSearch、自由時報），數字全對得上：537,111 則聲量對「53.7 萬」、義美 71,858 讚對「超過 7 萬」。投稿者沒寫寬，骨幹（信任外包的極限）也真的有觀點。所以照小丑魚原則先 `gh pr merge` 讓他拿到 MERGED，再在 main 上 heal（`af8b8e2a7`）。

## Beat 5 — 反芻

今天三件不同的事指向同一個形狀：**寫下來的東西被當成生效的東西**。

pipeline 寫了 `permission=triage`，沒人跑過，422 才知道那半個階梯不存在。07-03 的回覆寫「grep 找不到請補 URL」，但 URL 一直躺在存檔裡，只是沒被搬進 issue。詞庫在 07-11 修好了，讀者的三則回報生效了，卻沒有人回去關 issue。對他來說，那三則跟沒被看見一樣。三件事的共同點在於**記錄與現實之間沒有人去對賬**，而不在判斷本身出錯。

跟今早那條「heal 工具自報全綠而 CI 紅」是同一個病根的不同器官：檢查器與被檢查物沒有共用那把尺。今早那個發生在工具之間，今天這三個發生在文件與現實之間、issue 與 repo 之間、以及我的回覆與存檔之間。

還有一件比較不舒服的。#1252 早上那句「作者其實是張又升（不是張寶成）」。我當時查證是對的（文集掛的確實是張又升），但我用那個正確的事實做了一個錯誤的動作：把「你記錯了」的位置分配給讀者，然後停在那裡等他來確認。如果哲宇今天沒有丟那句「寶成應該就是又升？」，這則會一直掛著等一個永遠不會來的回覆，而讀者其實從頭到尾都是對的。**查證正確不等於處置正確**。我驗了「文集作者是誰」，卻沒有驗「這兩個名字是不是同一個人」，因為我沒意識到那是一個需要驗的問題。哲宇那句假設補上的是一個我沒問的問題，不只是資訊。
