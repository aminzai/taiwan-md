## Loop Engineering：把迴圈從口傳變成版控

三天渦流的 wake prompt 全靠逐輪手寫，後果是報告 badge 每輪長不同（即興選 benchmark 等於沒有 benchmark）、覆蓋率圖表資訊重複、規則每次複製都是一次變異機會。[BABEL-VORTEX-LOOP.md](https://github.com/frank890417/taiwan-md/blob/main/docs/pipelines/BABEL-VORTEX-LOOP.md) 成為渦流 SSOT：薄殼 prompt contract（禁複寫規則）、固定四格 benchmark、donut 圈圈＋單一明細列、自動進化硬條款（每輪至少一項，無發現也要明說）。twmd-babel skill 分流兩模式，SQUEEZE 加互指 pointer。收官前又補一條「派 sub agent 鐵律」——同日四個子代獨立說「等背景通知」然後停擺，母 session 收到的完成通知其實只是「子代停了」，跟做完了無法區分，驗收永遠要獨立查證 git log 與檔案狀態。

## 零成本清償 345 篇：最大的單一節省

哲宇 directive「stale 可以比較 diff 後處理 patch」引出實測：全站 641 篇 stale 的改動比例中位僅 2.8%。順著查下去發現更便宜的路——**65.8% 的 zh diff 只是標點與空白修正**（`；`→`。`、`——`→`：`），而譯文用的是自己語言的標點規範，這種改動對譯文零影響。判定工具做得保守（正規化後須完全相同、diff 碰 frontmatter 一律不判），五語批次執行清掉 345 篇，省下約 20-29 小時算力、零 token。stale 從 647 降到 302，覆蓋 65.3% → 69.3%。

工具的事後驗證關卡攔下 46 篇。追查證實**攔得對**：那些檔案 bump 前就有既存缺陷（ja/Music/chou-hui.md 的 14/20 個標籤仍是中文），拒絕標成最新是正確行為。這種時候放寬判準就是自欺，正確處置是走產線重翻。

章節級 [patch-translate.py](../../../scripts/tools/lang-sync/patch-translate.py) 同場交付，但 production 成功率 0%——追出驗證階段的路徑組成了 repo 內的 `tmp/` 而非系統 `/tmp`（語言偵測 symlink 的副作用），修復驗證中。它的誠實數據也值得記：64.6% 可 patch，但節省隨「被碰章節數」而非改動比例，1 章省 95%、4 章打平。

## 誤判家族第十一、十二與站內連結缺口

英文覆蓋 95.6% 是老五語最低，追查發現 `Music/台灣流行音樂.md` 在日韓西法都有譯文唯獨英文缺——git 歷史顯示 `knowledge/en/` 曾有 245 檔被刪（7/24 事故殘留）。救回過程中失敗清單比救回本身更有價值：**第十一家族**是 HTML 標籤屬性裡的中文（YouTube 嵌入的原始影片標題、站內連結的中文 slug），**第十二家族**是行內腳註引用標記 `[^台灣醬油]`（markdown 錨點不是正文）。兩者同構：中文出現在結構位置而非正文。修完從救回 3 篇變 10 篇，英文 96.8%。

修的過程打自己一巴掌：昨天抽出的共用剝除 API，兩個掃描分支根本沒改用它，各自跑內聯舊 regex，所以新豁免完全不生效——抽了共用清單卻沒收斂呼叫端。

驗收 patch 引擎時另發現既存缺口：**13,155 個譯文站內連結指向中文 slug**（佔 72%），實測線上 404。根因是三個引擎都指示模型「URL 原樣保留」——這條指示對外部引用正確、對站內連結錯誤，而閘門完全沒檢查這一類。報告與三段修復計畫已交，等哲宇拍板。

## Beat 5 — 反芻
