## 一個病的五張臉

通過率 58% → **16%** 的追查，最後收斂成一句話：**判準嚴格是對的，但終局
處置不該一律最重**。防護的成功率會直接變成產線的通過率。

| 現形        | 局部問題          | 原本的全域後果  | 處置              |
| ----------- | ----------------- | --------------- | ----------------- |
| armor token | 漏抄一個 URL 標記 | 整篇 exit=1     | 帶警告重試一次    |
| patch 章節  | 一章翻壞          | 整篇不寫        | 該章保留舊譯      |
| 腳註耦合    | 定義章翻壞        | （新發現）      | 改走全文重翻      |
| YAML 轉義   | 撇號寫法不同      | 判成 drift 擋下 | 解析器補 unescape |
| 失敗記錄    | —                 | 敗在哪查不到    | 補印項目名        |

第四個是**第十三個誤判家族，但形狀跟前十二個相反**——前面都是「譯文裡的
中文其實合法」，這個是**譯文沒問題，是尺歪了**。碰到高置信度的譯文被擋，
先驗尺再驗譯文。

第三個是修第二個時當場撞出來的：patch 部分保留首次觸發就被 verify 擋下，
因為失敗的是「## 參考資料」——腳註**定義**所在。保留舊定義、其餘章節更新
了**引用**，兩邊對不上。**章節之間不是獨立的**，腳註是跨章節耦合。

## 兩條方法論教訓（比 bug 本身重要）

**修完要複驗歸因**。armor 修復上線後通過率 16%→20%，看起來生效——但重試
觸發 **0 次**。改善另有來源，真主因（patch 章節否決）還在原地。先前的
「9/9 都是 armor」是重啟前舊 log 的樣本。**歸因要看機制證據，不是相關性**。

**規則寫下來不等於做得到**。今天下午才把「動手前先查既有工具」寫進
canonical，晚上修腳註判準時又自己造了一份 `FOOTNOTE_DEF_RE`，寫完才發現
同檔第 96 行早有 `FN_DEF_RE`。已改用既有常數——兩套判準分歧的風險比多寫
三行更貴，這是同日第四次驗證。
