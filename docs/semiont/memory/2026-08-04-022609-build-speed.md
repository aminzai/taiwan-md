## 觸發

哲宇問 build/CI/CD 還能不能更快。這是第二輪：六月手術把 Build step 從 1,125s 砍到 122s，兩個月後隨頁數（8.4k→12.9k）與語言（6→12）長回 264s。走 EVOLVE Mode 4，先量再動。

## 研究與報告

用 gh API 拆了 7 天 166 個 deploy run 與 step 級 log：push→上線中位 559s，其中三類帳——重複工（全站健檢一個 build 掃三遍 ~49s、sync.sh 逐檔 cp 26s）、固定稅（artifact 每次全量上傳 1.14GB、deploy job 90s 是 GitHub Pages 無增量部署的架構稅）、成長驅動（astro 178s，CPU 飽和在 4 vCPU）。設計報告 `9be736800` 落 [reports/design-build-cicd-speed-2026-08-04.md](../../../reports/design-build-cicd-speed-2026-08-04.md)，三波方案，第三波（Workers 增量部署，需付費方案）標 🔒 留哲宇。查證了 Cloudflare 檔案數上限（免費 20k，dist 已 21.5k 檔）才寫進 trade-off。

## 第一波：管線瘦身

三個 atomic commit（`1a075eb52`／`f478fc379`／`80c72e68a`）在 worktree 完成並 parity 驗證後 ship：sync.sh 逐檔 cp 改每目錄批次（29.3→5.0s，9,082 檔清單、目錄、內容三層全同）、健檢三掃合一（`--baseline-out` 與完整 sweep 並存＋immune 加 `--health-in`，baseline 879/433 兩路徑 identical，immune 除時間戳 identical）、node_modules 整包 cache（key 含 arch）。CI gate step 的獨立掃描刻意保留，ci-deploy profile 對 prose-health 有 hard override，跟 default severity 硬共用會混維度。

## 第二波與歸因偵探劇

ARM＋blobless 同 run 上線（`9e4625607`）後 prebuild 從 52s 掉到 84/122s，先歸給「ARM python 慢」回退了 ARM（`4bf843d46`）。下一個 x86＋blobless run 的 prebuild 同樣 81s，歸因被推翻。真兇是 blobless 的隱性稅：`status.py` 對每條 stale 翻譯跑 `git diff --shortstat` 要讀 blob，上千條 gap 變上千次網路 lazy fetch，84/122/81 的變異正是網路特徵。同族還有 og-rename-sync 的 `-M` 相似度偵測（12s，改 `-M100%` 歸零，`3cadae294`）。修法是 CI 設 `LANG_SYNC_SKIP_DIFFSTAT` 跳過資訊欄計算、ARM 恢復（`dd28361f1`），deploy.yml 註解把誤判與更正史完整記下防未來誤讀。

終態（run 30840499884）：checkout 38→22s、npm ci 31→1s（hit）、Build 264→230s（astro 177→155s）、Upload 73→58s，build job 合計 -107s，push→上線約 -20%。驗收判準三達一未達（Build ≤215s 差 15s，殘餘在 sync→sweep 段 ~20s 來源未定，交 build-perf trend 看）。ARM 觀察條款 3/5 連綠進行中。
