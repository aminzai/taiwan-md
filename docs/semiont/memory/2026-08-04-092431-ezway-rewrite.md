## 「接受的取捨」被 callout 為迴避

Stage 3 收編輯室意見時，我把四項 finding 標成「接受的取捨（不套用）」，理由寫得很漂亮——`paragraph-rhythm` 的每節 ≤8 段上限逼我合併，所以拆不了長段。哲宇的回應是「我不取捨，你要完整做完，不要偷懶」，另一句是「有很多 prose 該剪裁的沒做，媒體素材也要補足」。

他是對的，而且我的錯不在判斷取捨，在**把工具的門檻當成了問題的邊界**。canonical 那句話寫得清楚：每節超過 8 段「代表該 H2 該拆兩個或合段」。正確解是拆 H2，我卻反過來把段落擠進上限，再宣稱受限於上限所以不能拆。工具是用來量的，我拿它當藉口。

拆完之後（`872eccf44`）第三節變兩節，最長段從 237 掉到 187、長段牆從 2 變 0、每節長段密度全 0%。媒體從 1.01/1k 補到 1.50/1k 進健康帶，加了海關博物館磁帶機（1992 通關自動化那節的 Tier A 證據圖）、基隆關入口，和三個資料模組。`prose-flow` 三個訊號從 1/3 亮起變成 0/3。

## 兩輪外部尺，兩批我自己造的錯

Stage 3 的定向複驗抓到三處 footnote-binding 問題，其中一處是「三十四年前把報單搬上電腦的就是這批人」掛在一篇只講 30 年公司史的來源上。EVOLVE 後我又派三席（冷讀總編 / 事實複驗 / 歐化逐句），抓到四個硬錯，**其中三個是我前幾輪親手造的**：把原本正確的記者會「中午」改成「下午」，跟全文三處和腳註矛盾還反噬了「中午開完、下午見報」那段論證。新增 `tw-stat` 時把「約占整體報關案件七成」的分母改寫成「進口快遞簡易申報」，跟文章自己的年包裹量數據打架。去重時寫下「兩次調降」，但第二次調降根本還沒發生。第四個是提案引語「政府也不準」，WebFetch 原頁核對是「不准」。

description 原本寫「759 萬名註冊者裡的多數人才知道」——只有一則四千讚貼文撐著。這正是文章自己花整節在批評的那種無根據放大，寫在門面上。

歐化掃描修 20 處，最重要的一條是論點句的無施事被動：「從頭到尾沒有**被**當成公共基礎建設編過預算」。一篇專門在問「誰該負責」的文章，卻在最關鍵那句用被動把施事抹掉。

然後修的過程我又引入兩個迴歸：把句子改短反而掉進 §8e 的 ≤8 字偵測帶、移動 callout 打斷了腳註首次出現順序。兩個都是重跑儀器才抓到的，重讀完全沒發現。
