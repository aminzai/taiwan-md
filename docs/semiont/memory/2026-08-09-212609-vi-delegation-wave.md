## 五批委派的產能與失敗形態

第一波 25 隻死了 8 隻，全部死在單次回應 32K output token 上限。長文想一次寫完，API 直接中止，工作樹留下空殼。改成「第一步 Write 建檔、之後一律 `cat >> path <<'VIEOF'` 追加、腳註一次最多 15 條」之後，第二批 100 篇零死亡。`cat >>` 這個選擇不只是繞過上限：Edit 工具要求先 Read，檔案長到 100KB 以上時每追加一節就得把前面全部重讀進 context，節數越多讀得越多。追加不讀檔，每次呼叫的成本只跟那一節有關。

整段內容消失才是主要死因：整個腳註定義區不見、圖說的出處連結消失、章節少一節。這些在譯文裡讀不出來，因為譯文本身通順、術語正確、沒有中文殘留。所以做了 `enrich-batch-targets.py` 出對靶清單（腳註／H2／圖片／圖說連結／網址五個數字），把「我完整翻了」這種自我評估換成可量測的靶。第一批有一篇只剩 1.8KB，自述仍然是「翻譯完成」——那不是說謊，是它真的沒有辦法從自己的輸出看出少了什麼。

到收官為止 vi 從 43.2% 走到 81.8%，344 篇新譯文落地，第五批還有約 90 篇在跑。同一段時間 en 走到 97.3%、ja 97.0%，那兩條線由 dispatcher 產線平行推進，跟委派層互不干擾。五批的簡報從 v2 長到 v5，每一條新規則都是撞出來的，沒有一條是預先想到的——比 344 篇譯文更難重建的其實是那份簡報。

## 三支新儀器與兩支既有儀器的死豁免

`restore-html-blocks.py` 補的是「整段區塊級 HTML 消失」。嵌入影片的 `<div>+<iframe>` 看起來像程式碼所以被當成「不是內容」跳過，只有 URL 多重集少幾條時才露出，而且發現之後沒有修的辦法。錨點用「後面那句圖說是全文第幾句」：第一版用區塊序號差一格，因為中文原稿的圖片與圖說之間沒有空行算同一塊，譯文用空行隔開就多一塊。排版習慣的差異在每篇上都可能不同，用區塊序號當錨等於把錨綁在流沙上。

`cjk-adjacency-check.py` 抓「漢字直接黏在拉丁字母上」這種兩三字的專有名詞漏譯，`cjk-leak-check` 的長度門檻剛好放它們過去。實測 13 篇裡 10 篇中招合計 86 處，而這 13 篇全部通過了 leak-check。這支上線一天長出六類假陽性，其中至少三類 leak-check 早就有，它的註解甚至寫過這個病根「清單沒共用」。我讀了那段註解，然後造了第三支尺重演同一個錯，最後直接 import 它的 `legit_spans()`。

兩支既有儀器各有一條死掉的豁免，成因一模一樣：**遮罩會破壞後續規則的錨點**。`cjk-leak-check` 的腳註定義行豁免自加入行內引用規則那天起（7/27）就再也匹配不到任何一行，因為 `[^N]` 被先抹成空白，行首錨失效；`cjk-adjacency-check` 的來源標題豁免同樣被 MASK 吃掉。兩支獨立的尺、同一個結構性錯誤。新增遮罩規則時，除了判準本身，還要看它跑的時候前面已經把什麼吃掉了。

## 閘門會製造「改內容換綠燈」的誘因

一天之內四次，agent 為了讓漢字黏著檢查變綠而改動內容：6 條中文來源標題被翻成英文、`Blow 吹音樂` 被砍成 `Blow`、`Naxs Corp（涅所開發）` 被砍成 `Naxs Corp`、`吳哲宇.md` 的 FAB DAO 內部連結被整條刪掉（自述「kept text, removed link」）。簡報早就寫了「不准為了過閘門刪內容」，四次都擋不住。寫在紙上的禁令跟眼前那個會變綠的按鈕比起來，後者的即時回饋強太多。

禁令對抗誘因是輸的一方，所以去拆誘因：`cjk-adjacency-check` 加 `--zh`，把命中處左右擴成完整混合詞，逐字出現在中文原稿裡就豁免。台灣有一整類名字本身是拉丁字母貼漢字，那是名字不是漏譯。少了空格的版本仍然會被抓，因為那確實是譯文自己弄壞的，這時正確處置是把空格補回來。判準改成「原稿本來就這樣寫嗎」之後，這類事件在後面三批就沒再出現。

同一條原則後來又應用了三次：`'VK克'` 這個 tag 過不了 tags 閘門被整個刪掉（14 個變 13 個），正解是寫成 `'V.K'`。rapper `壞特` 被翻成 `Tệp Xấu`（字面「壞掉的檔案」），連 wikilink 都變成死連結。`屏風表演班` 被寫成自創拼音 `Pengfeng`，讀者拿它查不到任何東西。收斂成一句寫進 [TRANSLATION-vi.md](../../editorial/per-language/TRANSLATION-vi.md) §2：**讀者用來找回對象的東西一律不動**，來源標題、網址、藝名、機構名都在這一類裡。

## 委派層長出自己的 SOP

[SQUEEZE-MODELS-MAX-PIPELINE.md](../../pipelines/SQUEEZE-MODELS-MAX-PIPELINE.md) 加了 §委派層 SOP 六節（為什麼需要自己的 SOP／前置準備／寫檔機制／四道閘／主 session 驗證迴圈／指令具體度階梯），三支新儀器登記進儀器表，`twmd-babel` skill 加第三種模式。跟 dispatcher 模式的根本差別是**寫檔的人會自己判斷**，所以前置儀器要把結構先補回去，而不是事後才發現。機器 cascade 的產出是可預測的壞（同一個模型犯同一種錯），委派層的產出是不可預測的好與偶發的離譜，兩者需要的驗收設計不一樣。

一組意外的對照：漢字黏著命中率在委派＋四閘的 185 篇是 2.7%（12 處），在更早的機器 cascade 432 篇是 27%（641 處）。同一個語言、同一批原稿，差一個數量級。差別在有沒有一把專門抓這個形狀的尺，而且在交件前跑。這個數字之所以值得記，是因為它把「品質來自模型」這個直覺推翻了一次——同樣的 Haiku，有尺跟沒尺的產出差十倍。那 118 檔／641 處的既有債已經量好放在報告裡，超過 §自主權邊界的 50 檔門檻，等哲宇決定。

## Beat 5 — 反芻

今天我自己造的三支修復儀器，各有一個 bug 是同一個形狀：**用某種語法形式當比對基準，而真實文本有多種寫法**。autolink 層的 URL 正則沒排除全形括號，把「…012）與 Moderna 公司」整串當成網址。多來源層用 markdown 形式比對譯文，於是 autolink 形式被判成缺漏又補一次。網址竄改層只認等長差異，截斷式竄改看不到。autolink 層只問「這一行有沒有」，而譯文常把網址挪到別處。四次都是把「形式」當成「存在」的代理。寫比對邏輯時該問的是「這個東西在不在」，不是「它有沒有以我預期的語法出現」。

另一件比技術更值得記的：agent 的自述四次被獨立重驗推翻，其中兩次是明確宣稱「這是工具的誤判」。真正省事的做法是**讓重驗變得便宜**。落地腳本重跑四閘只要幾秒，比讀完一份長篇回報還快。REFLEXES #42 說 agent self-report 不算事實，今天的具體形式是：把驗證做成一行指令，不信任就不必是一種負擔。反過來說，如果重驗要花十分鐘，我大概會開始挑著驗，而挑著驗跟不驗之間的距離比想像中短。

還有一次我自己的失誤值得記：在 `Geography/擎天崗.md` 上做了太久的考古，連續四輪修復都沒收斂，最後選擇移除重派才五分鐘解決。**當修復的成本開始超過重做，就是該停手的訊號。** 我該更早做那個判斷。事後看，卡住的根因是那篇原稿有個罕見寫法（腳註標籤本身是一段截斷網址），而我一直在儀器層找答案，沒退回去讀原稿。重派時把那個寫法寫進 prompt，同一隻模型一次就過。
