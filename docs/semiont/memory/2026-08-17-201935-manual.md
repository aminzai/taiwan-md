## 閘門看不見換行的值

`b2fb41f3a`：ar 區塊還留著機器拼壞的專有名詞。TSMC 被拼成「تايكرو」（三處）與「تايوان سيكوندكتورز」，Foxconn 成了「فوكسيكونغ」，台光電被寫成台燿的阿拉伯拼法（連公司都認錯），金控譯成「融資與控制」，一句阿拉伯文中間夾著「民間」。

同一刀補掉閘門的結構盲點：它只認 `'key': 'value'` 同一行的條目，而 prettier 會把長值折到下一行。**越長的值越可能是整段沒翻的句子**，於是它恰好漏掉最該抓的那批。修完立刻現形：en 區塊六條 `data.category.*.desc` 整句中文、bench 的副句、resources 兩處「用戶」。新增 `CJK_FRAGMENT` 警示級抓「漢字夾在該語言的字中間」。

`f0bdb13f6`：那道新檢查報出七個語言 27 處，分四類。媒體名沒翻，en/fr/es 的時間軸寫「自由時報 + INSIDE」，而同一份 bundle 的 `about.press.ltn` 早就寫 Liberty Times。數字沒換算，`404萬人`、`16.4億`、`1979年12月10日` 就留在拉丁字母的句子裡。機關名翻一半，越南文「Hội đồng Dân tộc Nguyên住」是原住民族委員會翻到「原」就停了。還有俄文「фоно邂逅ует」，把邂逅兩個字插進動詞中間。

## 我的閘門擋到別人，修法是重校不是加豁免

`fe73c8a6c`：/budget 那個 session 推上 main 後 CI 紅，12 筆 `SIMPLIFIED_LEAK` 全是「占」。占比、占 GDP 是台灣的正常寫法，那頁的一手來源（主計總處歲出表）就寫「占」。閘門要求的修法會是把官方用字改成「佔比」。

用 939 篇中文文章重校才看清白名單有多小（它原本從 2,394 條詞庫欄位反推）：白名單外還有 173 種字元命中，前 20 名全是誤判：占 522、岩 422、斗 228、杰 186、双 73（作家楊双子）、虱 66（虱目魚）、丰 31（藍挹丰）。OpenCC 想把楊双子改成楊雙子、藍挹丰改成藍挹豐。一個做主權保存的站，閘門不該改台灣人的名字。

修法三件：白名單抽成 `scripts/tools/lib/tw-variant-chars.mjs`（原本註解就寫「跟 terminology-charcheck.js 同一份，勿各自維護」，然後今天就真的漂了）、補上 17 個語料校準出的台灣標準用字，並且分區：中文區塊放寬，非中日韓區塊維持嚴格。「湾／国／愿」刻意不進白名單：那些字在 knowledge/ 的腳註引用裡合法，但這兩支檢查器掃的是 src/i18n 與 data/terminology，在那裡寫「台湾」正是它們存在的理由。拿 A 語料的誤報率去放寬 B 語料的判準是量錯層。

## Beat 5 — 反芻

今天犯的五個錯是同一個形狀：**拿代理去量真正想知道的東西**。第一個是把 OpenCC 的 candidate 當「是不是簡體」（差點要別人改掉主計總處用字）、把漢字變少當「翻譯好了」（實際是被裸 key 取代，`/ar/data` 從 61 掉到 5 而讀者看到 `data.openData.heading`）、把報告的顯示上限當進度（40 筆讀成 23 筆還宣布有進展）、在主 repo 裡量 worktree 的檔案（第三次被 shell cwd 不跨呼叫保留咬到）、用跨行 regex 剝 `<style>` 結果從一行**註解裡寫的**標籤名吃到 1,700 行後的真標籤，把整份 body 挖空、還讓我一度以為文章頁那批寫死中文本來就是註解。

最後兩個工具缺陷是 subagent 追出來回報給我的：`blankStrings()` 三趟 regex 遇到 `"OSM's …"` 的撇號會弄壞引號配對造成**漏抓**，以及往前看 12 行的啟發法會從上面沒修的三元式漏進 `?`/`:` 造成連鎖假陽性。假陰性比假陽性難發現，因為沒有東西可以懷疑。

派工這件事也學到兩點。我給 dashboard 那隻 agent 的前提是錯的（說 `dashboard.ts` 沒有 zh-TW 區塊，其實有，我的 grep pattern 沒抓到帶引號的 key），它去查 git log 確認後照事實做，而不是照著我的錯前提硬幹，所以派工時附上「先驗證這個前提」比附上前提本身更有價值。另一點關於提醒的時機：兩隻 agent 踩了「丟背景指令然後等一個不會到的通知」（REFLEXES #42 v7 記過），我發預防提醒時它們已經進入那個狀態了，排隊送達的提醒防不了已經發生的事，要防這個只能寫進 spawn prompt 的第一段。
