## 爬取要兩條管道才拿得到完整素材

登入態的 Chrome 拿得到被引用貼文的全文，但 Threads 把留言清單虛擬化，捲動時舊留言會被回收，累積器掃完只留下 13 則。登出態的 Claude Browser 反而一次渲染 39 個容器拿到 33 則第一層留言，代價是所有引用區塊顯示「無法提供此內容」。兩邊取聯集才是完整的一則貼文，raw 落檔在 `reports/research/2026-08/threads-DcSu1TSkRMV-raw.md`。

值得記住的一個細節：Chrome MCP 開的分頁 `document.visibilityState` 是 hidden，IntersectionObserver 不觸發，所以無限捲動根本不會載入更多——height 卡在 4588px 不動。判斷「這個頁面只有這麼多內容」之前要先問「我看得到的部分是不是被瀏覽器省電機制擋住了」。

## 查證結果跟預期相反

留言區點名的清單是挺、肯定、行吧、具體、體現、聯繫、素質、核心、腦子、流量、水平共十一個詞。逐條查 moedict（教育部《重編國語辭典修訂本》）的結果：**十個查得到**。「挺」的副詞義「很、甚」有《兒女英雄傳》第三一回書證，例句寫「他人緣挺好。」，「肯定」有「必定」義項而例句是「看情形肯定會下一場大雨了。」，「行」則收了「同意、允許」義並舉「行不行？」。辭典接不住的只有「流量」——它只收物理義，人氣義確實是 2014 年中國「流量明星」之後的事。

所以本輪的核心發現是戰場位移：上一輪（8/04-8/05）盤的三波世代模型講的都是名詞替換，這則貼文帶出來的是副詞與功能詞層，變的是使用頻率不是詞的有無。這一層更難查，因為每個字台灣本來就有。

反方的論點同樣有理據，必須完整記下來。Threads 上經營「支語退散」系列的 @thiankiu.to 在 7/17 直接把方法論寫出來：「支語不是單看教育部辭典有沒有這個詞這麼簡單……台灣有『肯定』，中國也有『肯定』，但把『肯定』當作必定的意思在用就是支語。」這是對的。辭典是歷史語言的倉庫，收「挺」的副詞義靠的是一部清代京味小說，它能證明的範圍到「這個用法早就存在」為止，跨不到「台灣人日常這樣講」。每一條詞條都把這兩件事分開寫，不下判定。

## 差點自己造出假陽性家族

新詞刻意不加 detection 區塊（那批詞台灣文章天天在用，接進 quality-scan 會整批誤判），但忘了轉換器是拿全部詞條當規則的，不看 fork_type 也不看有沒有 detection。入庫後在本機測一句話，輸出是「他**蠻胸**站著，全場**力蠻**這個提案……**素質（台灣本有詞）**整齊，網路**點閱率**也很穩定」。四處把正確的台灣文字改壞了。

修法是給詞庫加 `auto_convert` 欄位（預設 true，2,400 條既有條目行為零變動），十條掛上不轉換，per-term 頁照常渲染照常解釋語感差異。轉換規則 4,015 → 4,000，再測同一句話五處正確用法原封不動，而同批入庫的「邪修→歪招」「薅羊毛→撿便宜」照常轉換。欄位說明寫進 `_template.yaml`。

這件事本身是本輪第二個發現：詞庫有三個出口（per-term 頁、quality-scan 偵測、轉換器），對「一條詞條有多可執行」的假設不一樣，但只有前兩個出口有開關。
