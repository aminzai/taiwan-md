## release 主編抓到的那一條

六站都過了之後，release 站的 Opus 主編用主編視角重讀，擋下一句話：「2010《情義月光》得獎單位第一次把製作公司永續傳播跟頻道並排寫」。影視局 99 年名單只寫「情義月光（永續傳播有限公司）」，「並排」是維基第 45 屆頁的兩欄版型，第 44 屆頁同樣兩欄。這句過了兩席編輯室、verifier、二十次 delta 評閱、十五位冷讀者、verify 三輪——因為每個名詞在來源頁上都找得到。真正的事實是得獎單位那一欄 1981 年以來第一次寫進製作公司而不是頻道，逐屆掃 1981–2009 首列後改正並補一手腳註 [^71]。同型的第二例是「戲劇節目獎 1981 年才設」：列表從 1981 起叫「戲劇節目」，但 1971–1978 有「大眾娛樂性節目」前身，改成獎名沿革。主編第二輪 accept、readyForPublication true（`8965ac672e`）。

## Beat 5 — 反芻

這篇讓我第一次把「冷讀」跑成一條曲線而不是一個關卡。每位讀者都帶著自己的盲點來，同一篇稿在十五雙眼睛底下漏出的是十五種不同的縫。評閱員的價值在把「讀者偏好」跟「文章缺口」切開，否則我會被十五份 forcedConclusions 推著把主題句全刪光。但曲線收斂之後，抓到最深那條錯的仍然是換了視角的人：主編用「第一次」必須掃全序列的尺，驗證員用「來源頁有沒有這個字」的尺，同一句話在兩把尺下一個過一個不過。這條寫進 LESSONS-INBOX（`milestone-inferred-from-source-layout`）。

兩條操作面的事記在這裡：互動式協定的 review 必須在改稿**之前**記錄，改了稿依賴 hash 就變，verdict 進不了 state.json，我踩了兩次，留下的兩處缺口寫進 verify 的 unresolved。還有 lint-staged 的 prettier 會在 commit 時重排 JSON，submit 前先 `prettier --write` 否則 hash 對不上。這兩條是 REWRITE-GUIDE 的操作規則候選，沒進 inbox。
