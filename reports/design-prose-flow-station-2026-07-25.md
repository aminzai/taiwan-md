# 順稿席與閱讀節奏儀器化

> 2026-07-25 23:55 +0800。外送專法 ship 之後哲宇讀完說：文段太長、閱讀順暢感掉了、後段幾乎沒有資訊圖表。
> 三句都對。而 ship 前 `article-health.py --profile=rewrite-stage-4` 是 hard=0 warn=0。

---

## §一 事實：所有閘門都是綠的，文章卻是牆

順稿前的量測（`957d295a4~1`）：

| 位置       | 觀察                                  |
| ---------- | ------------------------------------- |
| 後半 16 段 | 9 段 ≥ 200 字                         |
| 最密的 s6  | 8 段裡 5 段 ≥ 200 字（62%）、viz 掛零 |
| 前半 s1/s4 | 乾淨                                  |

這個比例要放進全站座標才看得出嚴重性。「單節內 ≥200 字段落佔比」在全站的分布是 p50=0%、p75=0%、p90=5%、p95=17%、p99=25%——**外送專法那一節 62%，落在全站最糟的那一小撮裡**。而它通過了每一道閘門。

（此處分布數字取自初稿的 ad-hoc 校準，量綱與 §三 B 的正式實測略有出入，原因與修正見 §三 B 的校準修正紀錄；結論方向一致。）

## §二 根因三層

### 2.1 儀器量的形狀不對（單段最大值 vs 長段密度）

`paragraph-rhythm` R4 抓牆的定義是**單段 > 280 字**。那 9 段落在 200–275，全部合格。

R4 校準時抓的是「一段 340 字的怪物」（蛋堡＋寶哥段）。它抓不到的是另一種形狀：**連續八段每段兩百多字**。單看每一段都沒破表，讀起來卻是一面牆——窒息感來自密度，不只來自峰值。

`viz-health` 同理：它數模組總數。全篇 6 個模組對 7 節就過，**完全不管它們是不是全擠在前半**。

### 2.2 順稿有規則、沒有閘門、沒有席位

`REWRITE-STAGE-3-VERIFY.md` Step 3.6.2 早就寫了順稿，而且第一句話就預言了今天：

> 外科手術疊幾輪之後縫線會留疤——成品**從頭到尾重讀一次**

它連「單段 > 280 字拆段」都列了。但它：

- **沒有產物**——沒有落檔，事後無法判斷它跑過沒有
- **沒有閘門**——不進任何 profile
- **沒有席位**——指派給主 session

而 Step 3.6 是三關綁在一起的，只有 3.6.1 原子重驗有 fan-out 產物。我跑完 3.6.1 的七個 verifier，就以為 3.6 完成了。這是 REFLEXES #15 的典型形狀：**規則要能執行才算規則**；沒有產物的 step 等於沒有 step。

### 2.3 順稿被指派給全場唯一讀不了新鮮的那個讀者

這一層最關鍵，而且今天已經被證明三次。

`docs/semiont/diary/2026-07-25-231820-外送專法.md` 記的是：我對派出去的代理有制度化的不信任（先落檔、再驗真偽、claim 只是線索），對自己只有意願上的不信任。今天三次自造缺陷全部由外部尺接住——冷讀總編抓到我自造的情緒槓桿、check 抓到我在零違規稿子上加的對位句型、儀器抓到我壓一個 warn 造出另一個 warn。

「從頭到尾重讀一次」對主 session 是**結構上做不到的事**。我剛剛才決定過每一句話該長什麼樣，那些理由跟句子是一起生的；重讀的時候，理由會先替句子辯護一次。順稿需要的不是深 context，是**沒有 context**。

而總編室（Step 3.7）已經是這個機制：Sonnet ×4-5、各自乾淨 context、禁讀藍圖與研究報告、falsification 姿態、落 `{slug}-chief-review.md`、`editorial-room-health.py` gate。它今天正常運作，抓到了「連死亡都只值 542 元」。

**它沒抓到牆，是因為五個探針沒有一個在問閱讀體感**——門面兌現、逐段主軸服務、H2 載體還原、連結成網、立體地愛，全部是論證與脈絡層。

### 2.4 為什麼牆會長出來（編輯粒度與檢查粒度錯位）

牆不是寫手寫出來的，是我修出來的。diary 記了同一輪的三連：合併段落造成牆 → 拆開段落造成切碎 → 補一段論證又造成牆。

每一次我都在**段落粒度動手**，而閘門在**全檔粒度報數**。全檔 warn 歸零我就往下走，從來沒有回頭看那一節整體變成什麼樣子。局部最佳化打地鼠，就是這樣打出來的。

## §三 解法四項

### A. 順稿升格為總編室第六探針「閱讀節奏席」（結構性修復）

把 Step 3.6.2 從「主 session 自己重讀」移到總編室，成為第六席。

| 項目 | 內容                                                         |
| ---- | ------------------------------------------------------------ |
| 席位 | 閱讀節奏（reading-rhythm）                                   |
| 模型 | Sonnet，乾淨 context，禁讀藍圖／研究報告／編輯歷程           |
| 輸入 | 成品全文 ＋ `prose-flow.py` 逐節輸出                         |
| 問題 | 哪一節讀起來窒息？哪一節資料密但沒有視覺承載？哪裡有縫線疤？ |
| 產物 | `{slug}-chief-review.md` 內一段（`### 總編探針 閱讀節奏`）   |
| 閘門 | 沿用 `editorial-room-health.py`，併入 ≤7 必改                |

**這一項不新增任何基礎設施**——總編室已經在同一輪跑，多派一個 Sonnet 探針的邊際成本接近零。它同時是本次進化裡唯一真正修到 §2.3 根因的一項。

### B. `paragraph-rhythm` 補 R5：長段密度（儀器補形狀）

```
R5：單一 H2 節內，≥200 字段落佔該節 prose 的比例 > 35%（且該節 prose ≥ 5 段）→ WARN
```

取 **>35%**，`≥5 段` 保護避免 2/4 這種小節誤報。soft-launch WARN（比照 R1–R4 與 quote-fidelity 慣例），vc ≥ 3 後再議升 HARD。

**實作後全站實測**（`article-health.py --check=paragraph-rhythm` 逐篇跑，非 ad-hoc 腳本）：

| 文章                         | 觸發節                                            | 比值        |
| ---------------------------- | ------------------------------------------------- | ----------- |
| 台灣美食總覽                 | §山林、海洋、家族遷徙：原住民、閩南、客家三層底料 | **4/6=67%** |
| Shopping Design              | §兩個廣告業出身的人，來教你怎麼看                 | **4/7=57%** |
| 曾博恩                       | §林森北 286 號 B1：算不準之後                     | **3/7=43%** |
| 斗笠／台北市／台灣無人機產業 | 各一節                                            | 40%         |

**6 篇 / 865 = 0.7% 觸發率**。順稿前的外送專法命中 `5/8=62%` ＋ `4/8=50%`——正是引發本次進化的那個 regression。

**交叉驗證成立**：前三名的台灣美食總覽與 Shopping Design 是**獨立於本次分析、早已被讀者 callout 過**的文章——後者正是總編室誕生事件引用的「形式閘門全綠但冷讀不成立」案例，前者是 5/18 callout。一個純形狀指標自己重新發現了兩篇已知有問題的文章。

> ⚠️ **校準數字修正紀錄（本節初稿寫錯過一次）**：初稿寫「14 節 / 11 篇 = 1.7%」，來自我現寫的 ad-hoc 腳本。它用 `re.split` 自己切段，**繞過了 `_split_paragraphs` 對 blockquote（策展人筆記）的排除**，把 callout 算進了分母。實作 agent 照規格做完後發現數字對不上，如實回報並查出根因，**沒有為了湊我給的數字去放寬過濾**。
>
> 更難堪的是：我為了驗證它的回報又現寫了第二支腳本，那支回報「R5 觸發 0 篇」——也是錯的（路徑不含 `knowledge/`，`_is_applicable_path` 直接 early return）。**同一個 session 裡我自己寫的臨時量尺錯了兩次，兩次都差點讓我做出錯誤結論**（第一次差點把門檻訂在錯的座標上，第二次差點誤判實作壞掉）。
>
> 這件事把 §三 D 的理由從「省 token」升級成「ad-hoc 腳本是未經驗證的儀器」。決議：**門檻不動**（callout 是視覺上獨立的框，本來就會打斷牆，排除它就閱讀節奏而言是對的，也與這支檔案一貫設計一致），改的是這份報告裡那組錯的數字。

### C. viz 分布**不做成閘門**（設計否決，附校準證據）

原本要加兩條：`連續 ≥3 節 viz 掛零` 與 `後 1/3 節 viz 總數為 0`。造工具的 agent 照 spec 實作後如實回報：**這兩條在順稿前的外送專法都不會亮**，因為那三個 0-viz 節並不相連，中間各夾著一個有 viz 的節。它沒有為了讓自己好看而放寬 spec，直接把設計錯誤指出來。

真正的形狀是**單一資料密集節掉到零**（8 段 prose、62% 長段、viz=0）。試著把它儀器化，兩種定義都失敗：

| 候選定義                           | 觸發率（母體：viz ≥ 3 的 46 篇） |
| ---------------------------------- | -------------------------------- |
| 節 prose ≥ 8 且 viz = 0            | 21 篇 = **45.7%**                |
| 資料 token 密度 > 15/1k 且 viz = 0 | 15 篇 = **35%**                  |

即使拉到最嚴的門檻仍打中三分之一。**這個維度描述的是語料庫常態，不是異常**——多數文章本來就有資料密但無圖的段落。35–60% 的告警率一週內會被訓練成無視，那比沒有閘門更糟（它會讓「全綠」這件事本身貶值）。

**結論**：viz 分布留在**判斷層**，不進閘門。

- `prose-flow.py` 的逐節表把 viz 欄擺在長段比旁邊，讓異常在同一列上自己現形
- 由 §三 A 的閱讀節奏席用判斷提問：「這一節的資料量有沒有超過散文能承載的？」

這是校準紀律正常運作的樣子：**設計了兩條規則，量完之後撤掉兩條**。寧可少一個閘門，不要多一個會被無視的閘門。

### B′. 順手修 R1/R4 的 prose 過濾漏接

造工具的 agent 另外回報：`check()` 建 `all_paragraphs_cjk` 與 `walls` 時用的是 `cjk >= 5`，**沒有接上 `_is_prose_block`**——但同一個迴圈裡 R2 已經接了。親驗成立（`paragraph_rhythm.py:270`）。

這是我 7/25 稍早修 R2 假陽性時只修了一半留下的。`_strip_for_prose_analysis` 不拿掉 markdown 表格，而表格是單一無空行區塊，`_split_paragraphs` 會把**整張表當成一段**——於是大表被 R4 報成牆，表格列拉低 R1 的 median 造成 atomization 假陽性。

改法：兩處都改用 `_is_prose_block`，與 R2 同尺。回歸驗收要求逐篇說明「不再觸發的篇目是真假陽性還是偵測力被弱化」，不接受只回報數字變小。

### D. `prose-flow.py`（新工具）

逐節報 prose 段數／最長／median／長段數與佔比／viz 數／媒體數，全篇報 viz 空白節清單與最長連續空白帶。

存在理由有三，第三個是本次進化過程中才長出來、也最硬的：

1. 給閱讀節奏席材料
2. **取代主 session 現寫 python**——本 session 為了診斷同一件事現寫了四次以上一次性腳本，確定性工作不該用推論 token 付帳
3. **ad-hoc 腳本是未經驗證的儀器**——我在本 session 現寫的量尺**錯了兩次**（一次把 blockquote 算進分母、一次路徑不合法導致 early return 回報 0 篇），兩次都差點做出錯誤結論。工具會被 dogfood、會被回歸測試、會被下一個人讀；一次性腳本不會。**用一把沒人驗過的尺去校準另一把尺，是 REFLEXES #65(f) same-DNA 的量測層變體。**

### E. 一條紀律：orchestrator 自修比照 sub-agent 收件紀律

> 主 session 親手改動 prose ≥ 2 段，該節必重跑量測，並進入下一輪外部尺。**不得以自己重讀代替**。

這條是 §2.3 的一般化，也是 diary 與 memory 兩處都已寫下的 LESSONS-INBOX 候選。今天的三次自造缺陷全部發生在「我正在修東西」的心情裡——那正是防備最薄的時刻。

## §四 哪些工作該給 Sonnet（回答哲宇問題後半）

判準沿用 §不對稱分工：**主 session 留靈魂深與裁決，派出去的是需要新鮮眼睛或確定性執行的**。

| 工作                   | 本 session 現況                | 該給誰              | 理由                                         |
| ---------------------- | ------------------------------ | ------------------- | -------------------------------------------- |
| 閱讀節奏冷讀           | 主 session（結構上讀不了新鮮） | **Sonnet 冷讀席**   | 需要的是沒有 context，不是深 context         |
| 逐節量測取數           | 主 session 現寫 python ×4      | **工具 prose-flow** | 確定性工作不該用推論 token 付帳              |
| 儀器假陽性修復         | 主 session                     | **Sonnet**          | 有回歸測試可驗收，判準明確                   |
| 裁決後的文字施工       | 主 session                     | **Sonnet**          | 決定在哪裡拆是手藝；拆本身是機械             |
| 事實原子重驗           | 已是 Sonnet ×7                 | 維持                | —                                            |
| 核心矛盾判定／投影論點 | 主 session                     | **維持主 session**  | 靈魂深，且今天被官方逐字推翻過一次，不可外包 |
| 主編匯流裁決           | 主 session                     | **維持主 session**  | 編輯室鐵律：匯流永遠主 session               |
| spine 型別判定         | 主 session ＋ 觀察者 in-loop   | **維持**            | §自主權邊界                                  |

本次進化已經 dogfood 這張表：`prose-flow.py` 由 Sonnet 造，門檻校準與 canonical 改寫留在主 session。

## §五 待觀察

1. **R5 soft-launch 誤報率**：6 篇觸發中有幾篇是真牆、幾篇是題材本來就密（法律／半導體這種概念密度高的題目可能天然長段）。0.7% 的觸發率偏緊，也可能代表門檻該往下調——但**要調得先有一把驗過的尺**（見 §三 B 修正紀錄），不是再現寫一支腳本。vc ≥ 3 前不升 HARD。
2. **閱讀節奏席會不會跟 R5 重複**：如果席位講的全是儀器已經報過的，代表席位問題設計太靠近工具，要往「念出來卡不卡」那種工具到不了的層次調。viz 分布那一問（§三 C 撤掉閘門後交給席位）是這一點的第一個實測。
3. **既有 6 篇要不要回頭 heal**：屬存量債，不在本次 scope；建議進 EVOLVE 排程而非一次補完。
4. **§三 E 那條紀律沒有儀器**——它靠自律，而今天證明自律在「我正在做正確的事」的時候最薄。若 vc ≥ 2 再犯，要想辦法儀器化（例如 heal commit 觸發強制重跑）。
5. **B′ 修完後 R1/R4 的偵測力**：假陽性拿掉之後，要確認不是連真訊號一起拿掉。驗收已要求逐篇判定，但 soft signal 的長期效果要看下一批文章。
