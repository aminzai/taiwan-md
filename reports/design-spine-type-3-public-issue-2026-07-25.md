# spine 第三型：多觀點立場議題探討矛盾型

> ⚠️ **本報告是 draft**。判準與護欄以外送專法一篇的實跑校準（REFLEXES #66：閘門判準必須用真實產出 dogfood 校準，不是憑想像設）。**該篇 ship 後回頭補「實跑數據」段再進 canonical**。

## 一、觸發與現況診斷

### 哲宇的 directive（2026-07-25）

> 「補充模式到 pipeline / dna 未來多一個 社會議題型的可以走『多觀點立場議題探討矛盾型』 像是房價 政策 環境 立場 教育等公共議題這些很適合」

### 現況：能力已存在，但**路由不到**

現行 [Step 0.1.5](../docs/pipelines/REWRITE-STAGE-0-VIEWPOINT.md) 是「立體群像＝預設畫布 ＋ 7 手法選單 ＋ 矛盾驅動需 unlock_reason 才解鎖」。
哲宇描述的「多觀點立場議題探討矛盾型」，在現行語彙裡**已經可以表達**＝**矛盾驅動主脊 ＋ 手法 5 多元視角並陳**。
[REFLEXES #77](../docs/semiont/REFLEXES.md) Boundary (c) 甚至已明文允許今天發生的事：「beloved 題若 research 過程真的挖出 genuinely contested 面向且哲宇 in-loop 拍板，可 override 走矛盾 spine」。

**所以缺的不是能力，是三件事**：

1. **這個複合型沒有名字，所以不會被選中。** 外送專法的研究報告自己就寫了「本題確實是真實公共政策爭議，符合 Step 0.1.5『政策辯論』的矛盾驅動候選條件」，然後**還是判了立體群像**。理由寫在報告裡：「若強行選一條 thesis 當整篇主脊，會把其他三方壓成配角」。這個顧慮是對的——但它反對的是**單軸矛盾驅動**，不是反對「矛盾當脊椎＋多觀點並陳」。**因為第三型沒有名字，session 只能在「立體群像」與「聽起來像選邊的矛盾驅動」之間二選一，於是選了安全的那個。**
2. **反向閥門偵測到了，但沒有目的地。** 20 persona gap-audit 的三軸反向閥門（B／C／D）各自獨立驗出「立體群像在這題會撫平三種真實的不對稱」。機制**成功偵測**。但 Step 1.9.7 反向閥門的路由只寫「回 Step 0.1.5 重判」，而 Step 0.1.5 的 default 硬度是「**拿不準 → 立體群像**」——偵測因此沒有轉成重判。**是觀察者的一句話補上了那個目的地，不是機制自己走到的。**
3. **`default 硬度` 對「政策辯論」這類題目過度保守。** v7.7 的硬度是針對「受愛戴人物／機構被寫成反例」的病（金曲獎 v1、施振榮 v1，都是**人物與機構**題）。把同一個硬度套到「房價／能源／教育政策」這種**題目本身就是一場公開的、多方都有正當立場的爭論**，會把該有的張力也一起壓平。

## 二、第三型跟前兩型的邊界（本報告的核心貢獻）

|              | 立體群像                                     | **多觀點立場議題探討矛盾型（新）**                                       | 矛盾驅動（單軸）                     |
| ------------ | -------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------ |
| 適用         | 受愛戴的人／機構／傳統／地方／集體記憶／工藝 | **公共議題**：房價、政策、環境、能源、教育、勞動、都更、移民             | 內在張力人物、單一可辯的 claim、醜聞 |
| 矛盾的地位   | 一個 facet（手法 1 為輔）                    | **脊椎，但矛盾是「結構性且未解」的**                                     | 脊椎，且文章替一個 thesis 辯護       |
| 論點形態     | 統合式洞見（這群面向合起來說出什麼）         | **「這場爭論的形狀是什麼」＋「誰的帳沒被算」**                           | 可被反駁的主張，文章證明它           |
| 收束方式     | 慶祝＋理解＋廣度                             | **不收束成一方勝出**；把判斷交還讀者，但**明確指出爭論的重心被放錯在哪** | 收束成一個立場                       |
| 讀者離場狀態 | 「原來如此，真好」                           | **「我知道這件事在吵什麼、也知道自己還缺哪一塊判斷依據」**               | 「我被說服了／我想反駁」             |
| 最大失敗模式 | 寫成慶祝式面向清單（維基化）                 | **兩個**：(a) 退回立體群像＝把不對稱寫平 (b) 滑成單軸＝選邊炎上          | contrarian thesis 硬塞受愛戴題       |

**一句話判準（給 Step 0.1.5 用）**：

> 問「**這件事在台灣社會現在正在被公開爭論嗎？而且爭論的各方都有正當立場（不是誰明顯無理）嗎？**」
> 兩個都 yes → **第三型**。
> 第一個 yes、第二個 no（有一方明顯站不住） → 單軸矛盾驅動。
> 第一個 no → 立體群像畫布。

這個判準把「拿不準 → 立體群像」的兜底**收窄**：拿不準**且不是進行中的公共爭論** → 立體群像。是進行中的公共爭論 → 不准用「拿不準」躲進立體群像。

## 三、第三型的專屬紀律（全部來自外送專法實跑，非想像）

這六條是這一篇真的踩到、或編輯室真的攔下來的，不是推演出來的：

1. **政治歸屬之爭不得承載 thesis 重量。**
   外送專法 v1 論點末句把重量掛在「這部法該記在誰頭上」的藍綠白攻防上。結構席與炎上席**各自獨立**命中同一點（雙席同時命中＝強訊號）。政黨攻防是噪音、撐不起論證，還會命中 §自主權邊界。
   **紀律**：政治攻防素材降為「一句中立並陳」，功能限定為對照；thesis 改由**制度性事實**承載（本篇改為執法究責：工會控訴 vs 部長表態 vs 稽查量能查無）。

2. **每一方要有自己的逐字聲音；陣營內部的光譜不可被單一發言人收攏。**
   本篇最大的 falsify 是「工會不是單一聲部」——蘇柏豪「血淚換來的成果」與陳昱安「立來供著？看爽的？」出自**不同組織**，前者是感謝式、後者是監督式。若用一個發言人代表全體，就把真實的路線之爭消音了。
   **加碼發現**：連「代表 14 萬外送員」這個數字都無法驗證（該組織是聯盟非工會、無會員名冊）。**引任何一方發言時不得暗示它代表該方全體。**

3. **「誰手上有麥克風」的不對稱本身是一個 facet，不是要抹平的瑕疵。**
   本篇四方裡店家最薄——連一句具名發言都難找，且法律只給店家「範本」而給外送員與消費者「法定強制清單」。這個不對稱是內容，不是研究不足。

4. **但沉默不可被代言。**
   persona C 軸假設「店家不敢批評平台怕被下架」，增補查證**無法證實**——更可能是媒體資源沒投入這個角落。
   **紀律**：如實寫「找不到」，並列出找不到的兩種可能原因，**不選一個當結論**。（編輯室評這是本篇執行「立體地愛」最紮實的一處。）

5. **關於「討論本身」的 negative finding 是合法內容。**
   本篇查證：**台灣中文論述裡沒有任何人用「妥協」框架定性這部法**，連進步派英文媒體也沒有；勞權界吵的是「夠不夠、會不會被架空」不是「該不該存在」。
   誠實寫出這個空白，比硬塞一個邊緣的「妥協派學者」更符合論點。**第三型特別容易誘發「為了平衡而製造反方」——negative finding 是對治它的工具。**

6. **官方的「不回答」是可寫的主體。**
   本篇最強的一次翻轉是發現：法律**從未**對「算不算員工」下判斷（第 1 條第 2 項雙軌），而全網通行的「去身分、重權益／第三類勞動者」是維基與商周的二手 gloss。
   **紀律**：公共議題題型必須**把二手 gloss 跟法條／官方文件原文分開查**。第三型的題目幾乎都有一層「大家以為它說了什麼」——那層本身值得拆。

## 六、一個誠實的自我觀察

這條 directive 之所以有價值，不是因為 pipeline 缺一個功能，是因為**我今天在有完整判準、有反向閥門、有 unlock 條文的情況下，仍然選了保守的那一個**，而三軸 persona 早就把證據攤在我面前。哲宇的一句話沒有給我新能力，是**把我已經有的能力接上了開關**。

這正是 REFLEXES #73「查證反射 < 建造反射」的另一個形狀：規則早就寫在那裡（Boundary (c)），我讀過 Step 0.1.5，也讀過反向閥門的定義，但**當下沒把它們接起來**。第三型要解決的，一半是分類學問題，一半是**讓正確的選項不需要「override」這個動作就能被選中**——因為需要 override 的選項，在無人在場的 cron 場景幾乎不會被選。
