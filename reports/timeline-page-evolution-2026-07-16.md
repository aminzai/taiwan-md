## 一、v1 的誠實評估（六個維度）

v1 在幾小時內把骨架立起來：分期正確、資料層乾淨、六語可用、事實查核過。但拿「臺史博的一個展廳」當標準重看，弱點很清楚：

### 設計

v1 是一份**排版好的清單**，還缺「策展的空間感」。博物館的每個展區有自己的房間：燈光、牆色、展區編號、導言板。v1 的八個時代只有 accent color 一個變數在區分彼此，滑過去的感覺是連續捲動一份文件，而非走過八個房間。

### 內容

三個缺口。第一，**人沒有被放到前景**：博物館用面孔錨定時代（蔣渭水的眼鏡、莫那·魯道的獵槍），v1 把人物文章混在一般文章格裡，跟一篇小吃文章視覺權重相同。第二，**事件是死的文字**：「1947｜二二八事件」明明站上有一篇 A 級文章，事件行卻不可點——v1 實作報告自己就把這條列為後續候選。第三，**序章太薄**：分期方法來自曹永和，站上有整篇〈臺灣島史觀〉，但 v1 只放了一句沒有出處的斜體引言，讀者不知道這句話有一整篇文章可以追。

### 架構

資料層（timeline-eras.json）的骨架健康，可加而不必改：`figures`（人物列）與 `events[].link`（事件連結）都是加法欄位，template 向下相容。缺的一塊是**機器可讀層**：頁面對 AI 爬蟲是好的 semantic HTML，但沒有 JSON-LD——對一個以 AI-SEO 為主權戰略的站，時間軸這種結構化內容是最該有結構化資料的頁面。

### 層級

v1 的每時代內部層級是「導言 → 事件 → 主幹卡 → 文章格」，合理但有一個混層：**人物既是內容也是導覽**。把人物從文章格抽出來變成獨立的一列 chips，文章格瘦身、人物變成時代的臉，層級才對。另外終章只有兩個 CTA，漏了最自然的一條互導：**地理台灣 ↔ 時間台灣**是同一批文章的兩條軸線，兩頁應該互相指著對方。

### UI/UX

三個實測發現的粗糙面。(1) hero 的 eyebrow 跟 title 都是「時間台灣」，重複；eyebrow 該做眉題的工作（說明這是什麼），不是把標題唸兩次。(2) era chip bar 在手機上會橫向捲動，但 active chip 變化時**不會自動捲入視野**——滑到當代時，亮著的 chip 在畫面外。(3) 頁高 13K px，讀者沒有「我走到哪了」的整體感；chip 只回答「我在哪個時代」，不回答「還剩多少」。

### 視覺

字體層級可以，但缺一個**巨大的東西**。博物館展區入口都有一面大字牆。v1 的時代 header 最大的字是 2rem 的標題，年代範圍反而只有 1.05rem——在時間軸這種頁面，**年代才是空間座標**，應該大。

## 三、想過但否決的（記錄用）

- **每時代配歷史圖片**：站內文章 image 欄覆蓋率低（854 篇僅 37 篇有圖），要補就得走 Wikimedia 授權查核流程，是獨立的媒體批次任務，不塞進本次（媒體增補批次已有既有軌道）。
- **「同時期的世界」對照事件**：博物館常做，但每條世界史事實都需要站外查核，站內沒有母文章可依靠，違反「事件年份必須對站內已查核文章驗證」的 v1 紀律。等有〈台灣與世界史對照〉類文章再接。
- **等比例時間軸**：史前 3 萬年 vs 當代 25 年，比例尺在視覺上不可行；博物館也不做等比展廳。
- **scrollytelling 動畫**：graph.md v3 路線圖項目，等 CSS scroll-driven 範式在文章層先驗證，本頁維持內容零 JS 依賴。
- **人物頭像**：授權與覆蓋率同圖片問題；文字 chips 先行。

## 四、驗證計畫

v1 同規格：六語 production build 綠燈、link gate 零新斷鏈、亮暗雙主題＋手機 smoke test、事件連結與人物 chips 逐語言抽驗；新 JS（捲入＋進度條）失效時頁面功能完整（漸進增強）。

## 五、實作紀錄（v2 ship）

九項全數落地，另外在實作中多修了一個報告沒預見的問題：

- **人物短名的啟發式會被標題咬到**：原設計從文章標題「名字：副標」切短名，實測 26 人 × 6 語掃出 11 個壞格——馬偕的標題以格言開頭（「寧願燒盡，不願鏽壞」六語同型）、韓文用破折號分隔、鴨母王綽號連名。修法是把人名升級成策展資料：`figures` 從 slug 字串改為 `{ref, name}`（name 六語，從各語標題自動抽取＋人工校 11 格），template 有 name 用 name、沒有才退回啟發式。人名跟年份一樣是穩定的策展資料，該住資料層。
- 資料層：`figures` 26 人（People 從文章格抽出＋補 11 張新面孔）、`events[].link` 35/40 條事件接上文章。
- 驗證：六語 production build 綠燈、link gate 0.41%（時間軸零斷鏈）、亮暗雙主題＋窄版 smoke test 過；zh/en/ja 人物 chips 抽驗（馬偕／George Mackay／マッカイ 各自正確）；JSON-LD ItemList 8 時代（production 絕對網址）；chip 自動捲入與進度條實測動作。
- 順手發現並開 chip：newsroom 的 `dashboard-newsroom.json` 在乾淨環境起 dev server 會 SSR 崩頁＋未進 gitignore（非本次範疇）。

## 六、上線後 hotfix：scrollIntoView 綁架頁面捲動（哲宇 callout）

v2 上線後哲宇回報「頁面上的 scroll 變超怪」。病根是九項裡的第 6 項：active chip 自動捲入用了 `scrollIntoView`——它的規格是把「所有可捲動祖先」一起捲到位，頁面本身就是祖先之一。全站 html 又開著 `scroll-behavior: smooth`，於是每次 IntersectionObserver 在使用者捲動途中觸發，瀏覽器就啟動一段平滑動畫去「微調」頁面位置，跟使用者的捲動互搶——就是那種捲到一半被拉走的手感。

修法（`timeline.template.astro` script）：改成只對 chip bar 這個水平容器自己 `scrollTo`（置中 active chip、bar 不溢出時完全不動作），並加 currentActive 去重讓同時代的重複觸發不做事。驗證：四個瞬移位置斷言頁面捲動座標分毫不被 chip 邏輯改動（全過）、chip bar 水平軸正常捲動。教訓一句話：**在捲動驅動的回呼裡永遠不要 scrollIntoView，要捲哪個容器就直接捲那個容器**。
