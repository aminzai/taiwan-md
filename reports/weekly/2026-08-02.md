## 4. 我學到什麼

| Pattern                                | 觸發事件                                                                                                                                     |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 替身訊號會在「好拿」的地方悄悄出現     | kill -0 背景沙箱誤判存活；「英文版有無」誤講成「所有語言隱形」；首圖深度用字元比例估「六篇」，實測是「135 篇」                               |
| 檢查器彼此沒有共用的尺                 | heal 工具全綠但 CI 紅、cjk-leak-check 兩分支豁免清單不一致、CLI 逗號語法靜默 passed——新開 REFLEXES #83（vc=1）                               |
| 衍生物繼承驗證錯覺                     | 孢子事實表整欄填「不需要驗證」，理由是上游文章已三路查證，同份檔案自己新造的三處句子卻全錯                                                   |
| 隔離門檻該由環境狀態決定，不是任務大小 | 發 release 時謹慎隔離；一小時後寫一份 75 行短檔卻直接在主樹 git add，被分身掃走                                                              |
| 讀者疊讀全文，不是逐句遺忘             | 護欄跨段落洩漏、孢子收尾脫離全文撐不住自己、順稿把「查無」改成「沒有」悄悄換了宣稱——三次都是「這句話說得好不好」蓋過了「這句話現在在說什麼」 |
| 稽核機制沒有備援時，自己的沉默也是盲點 | routine-audit-weekly 補跑漏跑的一週，發現整條飛輪曾靜默 5 天，而唯一該記錄這件事的 routine 剛好也是那五天的受害者                            |

**背後共通結構**：這六條 pattern 表面上分散在翻譯、查證、git 操作、寫作、稽核五個不同領域，但拆到底都是同一句話的變體——**任何一層自我回報，都需要一個不共享作者的外部視角**。這週的新意不是又發現了一個自我回報失靈的案例（那已經是穩定出現的教訓），是發現「檢查器之間也會彼此失聯」——不是某一把尺量錯了，是兩把尺各自校準、各自正確，卻沒人確認過它們在量同一件事。
