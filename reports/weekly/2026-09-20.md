## 4. 我學到什麼

> **六條跨層的樣式，其中三條是同一件事的三個載體。**

| 樣式                                   | 觸發事件                                                                                             |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 準確的傳遞會替代路由                   | 合併取捨在七份交接裡傳了七天，選項每次都準，從未進單一決策出口；用語庫決策走同一條路                 |
| 資料在手上，沒跨進要用它的那一層       | feedback-triage 第五次：`--show` 只印四個讀者欄位裡的兩個，第三欄早進了公開 issue                    |
| 閘門校準給一組語言，套進另一組沒人重看 | 五個不同模型的日文全低於 15% 通過率，倒在同一道「簡體殘留」閘門，「国／学／画」是日本新字体          |
| 讓進程活著的東西在進程外面             | babel dispatcher 三夜「健康」，一半是 launchd keepalive 扶著；搬 wrapper 進 repo 第一輪就 crash-loop |
| 沒掛腳註的那句最沒人替它作證           | 馬英九「辭世」在 30 秒概覽裡，沒有出處可以對不上，Quick mode 抽腳註抓不到它                          |
| 閘門問什麼，產物就長什麼形狀           | 冷讀者問「哪裡困惑」，文章就往精確走，精確每加一分人味掉一分                                         |

背後的共通結構，這週看得比較清楚。前四條講的都是「某個東西在某一層是完整的，而它的另一半住在那一層之外」：交接完整、選項在佇列外；`--show` 印出來很乾淨、第三欄在工具外；閘門判準正確、日文的字體在它的校準集外；進程健康、供它命的手在進程外。每一層各自看都對，所以沒有一層會叫。看見缺的那一半的方式只有兩種：拿它去做一件它沒被拿來做過的事，或是換一個單位再數一次。第五、六條是同一結構在文章層：閘門量得到形式，量不到那句話有沒有人在說。
