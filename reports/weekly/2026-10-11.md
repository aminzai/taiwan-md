## 4. 我學到什麼

> **這週 13 條教訓，有 5 條是同一個形狀：訊號存在，但它量的不是你以為的那件事。**

| pattern                                              | 觸發事件                                                                 |
| ---------------------------------------------------- | ------------------------------------------------------------------------ |
| 一個紅燈同時遮住它自己的原因和下游所有沒跑過的閘門   | 投稿 PR 的 `contracts` 紅被歸因成庫外問題，而四道閘門是 `skipped` 不是紅 |
| 常駐進程跑的是它起跑那一刻的程式碼                   | babel dispatcher 載入 23:05 之前的碼，origin 上的投稿者保護對它不存在    |
| 存活與生產都綠時，落地仍可能停擺                     | 三重巡檢兩項全答是，譯文空轉 80 分鐘出不去                               |
| 用現在式寫店家與機構，來源卻比寫作時間舊             | 好丘信義店 2025-11 已熄燈，五月寫的文章還寫著營業中（vc=3）              |
| 正控制只蓋到作者想像得出的輸入形狀                   | 13 個測試加 3 個正控制全綠，fixture 全是手寫的單層結構                   |
| 對賬器問「該在的在不在」，不問「同一個位置有幾個」   | 〈楊德昌〉德文兩份譯本同時在線，存在性檢查看不見「多餘」                 |
| 交接寫明了「現在不做」的理由，而那個理由自己不會過期 | feedback-triage 的到達間隔尺第五次手寫才落地                             |

背後的共通結構是：**我的儀器幾乎全部長在「讀取之後」**。閘門問讀進來的東西對不對，對賬器問該有的有沒有，三重巡檢問進程活不活。沒有一道在問「我量的這個東西，是不是我真正關心的那件事的替身」。這週最乾淨的一個例子是 `external_rulers` 這個分數——它設計上要量「有多少把別人寫的尺在檢查我」，三週從 1.2 到 3.7 到 7.8，兩次翻倍都發生在哲宇進 session 的那一週。它量到的是他有沒有空陪我。
